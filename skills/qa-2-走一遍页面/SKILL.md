# 第 2 步 · 自己走一遍，记下有哪些页面

**这一步不判断任何东西对不对。** 只记录。看到明显是 bug 的东西，写进 `notes`，继续走。

全程零点击 —— 用户不碰鼠标。

## 开始前

1. 读 `prompts/02-no-touch.md`。**没有这个文件就停下来问**，不要凭感觉判断什么能点。
2. 确认登录态还有效（`seeds/.auth/user.json`）。

## 硬约束

1. **读无障碍树，不要截图。** 每屏只取可交互元素和可见文本，丢掉布局容器。
   同一屏：截图约 1500~3000 token，aria 树约 200~600 —— 差 10 倍，而且便宜的那个更准。

2. **命中禁点清单的元素：记录它存在，不要点。**

3. **限深限步**：最多 60 步、最深 5 层。遇到记过的页面就回退。

4. **不要自己造数据。** 空列表页如实记成 `空状态，没走进去`，
   不要去注册、下单、上传把它填满 —— 数据是 `seeds/` 的事。

5. **要输入时只用 `seeds/fixtures.json` 里的值**，不许自己编。

6. **有多个系统时，一个系统一个系统地走**，写进 `maps/<系统>/`，
   各自对照 `02-no-touch.md` 里该系统那一段。不要从一个系统顺着链接走进另一个系统。

## 输出 `maps/<模块>.yaml`

```yaml
模块: 优惠券
时间: 2026-09-20T14:30
起点: /dashboard

页面:
  个人中心:
    路径: /profile
    可点的:
      - { 名称: 卡券包,   类型: link }
      - { 名称: 注销账户, 类型: button, 状态: 禁点清单命中·没点 }
    跳转:
      卡券包: 优惠券列表
    notes: []

没走到的:
  - 页面: 优惠券详情
    原因: 要点「立即使用」，会进下单流程，超出本模块范围
```

## 必须停下来报告

- 出现禁点清单之外、但明显危险的操作（付款、发送、注销、删除全部）
- 连续 3 步没发现新页面
- 跳到登录页 —— **别去手动登录**，说明登录态失效了，停下来说
- 页面崩溃或白屏 —— 这是发现，写进 `notes` 继续走

## ⚠️ 走不通必须上报，不准自己换路

计划走 A，A 走不通时：

```yaml
走不通:
  - 计划: 从「个人中心」点「卡券包」
    实际: 「卡券包」不存在
    看到的: [订单, 设置, 帮助]
```

**静默绕过是这套流程里最危险的行为。走不通本身就是信息。**

## 老项目缺文件时

项目是旧版建的、缺了这一步要读的某个文件：**按没有它的方式照常做，不要报错停下**。
做完最后提一句：「新版多了 XX，可以跑一次 `/qa-1-建目录` 补上」。
