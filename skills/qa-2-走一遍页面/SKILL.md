# 第 2 步 · 自己走一遍，记下有哪些页面

## 开口第一行：报版本

开始做之前，**第一行单独写**：

```
QA 流水线 v1.3.4 · qa-2-走一遍页面
```

就这一行，不加别的话，像软件标题栏那样。直接写出来，不用放进代码块。
版本号就是这个文件开头那行注释里的 `version`，**不要去磁盘上读文件来报** ——
你报的必须是你现在加载的这一份。学员出问题时，作者靠这一行知道他跑的是哪一版。

接着顺手比一下（找得到就比，找不到就跳过，不要卡住）：

- skill 目录里 `qa-更新/版本.json` 的版本比你报的新 → 这个对话加载的是旧版。
  告诉用户「skill 已经更新了，但这个对话还在用旧版，请重启 AI 工具或者开一个新对话，再打这个命令」。
  他说「继续」，就照你现在这一版接着做，不要拦着
- 项目里 `.qa-ai.json` 的版本比你报的新 → 这个项目是更新的版本建的，提醒他先打 `/qa-更新`

这一步新写或改过的文档（地图、覆盖表、用例清单、报告、问题单、变更单），标题下面写一行
`生成：QA 流水线 v1.3.4 · qa-2-走一遍页面 · <日期>`。改已有的文档，把这一行改成这一次的。

**这一步不判断任何东西对不对。** 只记录。看到明显是 bug 的东西，写进 `notes`，继续走。

全程零点击 —— 用户不碰鼠标。

## 开始前

1. 读项目根目录的 `项目适配.md`，这个项目的做法和踩过的坑都在里面。
   **没有就当场建一个**：按 `qa-1-建目录` 那个 skill 目录里的 `项目适配模板.md`，
   只建这一个文件，别的不动，建完告诉用户。第一次跑踩的坑最多，没地方写就全丢了。
2. 读 `提示词/02-禁点清单.md`。**没有这个文件就停下来问**，不要凭感觉判断什么能点。
3. 确认登录态还有效（`测试数据/登录态/` 下对应角色的那份）。
   **同一个浏览器里，一个站点只能登一个账号**。要换账号，就换一个互相隔离的浏览器环境，不要在同一个里退出再登。
4. **读 `地图/覆盖表.md`**。有 → 这是接着走，看用户这次要走哪块（见「接着走」）；没有 → 第一次，从「先读骨架」开始
5. **告诉用户能不能看、怎么看**。你用的浏览器他看得见吗？看不见就直说，并告诉他打开的办法。
   不要让他以为你在操作浏览器，却什么都看不到。

## 先读骨架（几分钟）

不管后面怎么走，**第一次都先把整个站的骨架读出来**：

- 每个菜单入口点进去，**只读这一页的一级标题和主要按钮**，不往深处走
- 用户菜单、顶栏里的入口也算
- 写进 `地图/覆盖表.md`：每个模块一行，有哪些页面、看得到哪些表单和弹层的入口

骨架读完，你就知道这个站有多大，才能跟用户说清楚两种跑法各要多久。

## 让用户选跑法

把骨架报给他（几个模块、几个页面、几个表单），然后**让他选，说清利弊**：

| 跑法 | 走什么 | 好处 | 代价 |
| --- | --- | --- | --- |
| **先跑核心流程**（第一次推荐） | 一条从头到尾的主干业务，比如「建商品 → 建批次 → 发标签 → 消费者扫码看到」 | 半小时左右就能走到出报告，**马上看到这套东西有没有用** | 只覆盖这一条线，别的模块没走、没用例、没测 |
| **全部走完** | 覆盖表里每个模块、每个页面的功能点 | 一次把全项目摸清，后面出的用例是全量的 | 按骨架估时间告诉他（见下），token 也多几倍 |
| **指定模块** | 他点名的那几个 | 只测这次改了的地方 | 别的不知道 |

**估时间**：按骨架的大小报一个大概的数，比如「13 个模块、10 个表单，全走完大约 1 到 3 小时」，
并说明这是粗估。走过一次的项目，按上次每个模块花的时间估，更准。

**核心流程是哪条，你提一个，他定。** 从首页的产品介绍、菜单的顺序里找：
这个产品存在的理由是什么，从开始到最终用户看到结果要经过哪几步。

**他选了先跑核心流程，收尾时必须说清楚两件事**：
- **这次只走了哪条线**，覆盖表里还有几个模块没走
- **以后怎么接着走**：打 `/qa-2-走一遍页面`，说「继续走没走的」「走商品库」或者「全部走完」

## 覆盖表 `地图/覆盖表.md`

**这张表是全项目覆盖的标准**：每一格要么走过了，要么写着为什么没走。
也是**下一个对话的记忆** —— 新开的对话读它就知道走到哪了，不靠聊天记录。

```markdown
# 覆盖表

模块 13 个：走完 3 个、走了一半 1 个、没走 9 个。核心流程：建商品 → 建批次 → 发标签 → 扫码（已走完）

| 模块 | 页面 | 功能点 | 类型 | 走了没 | 用例 |
| --- | --- | --- | --- | --- | --- |
| 商品库 | [商品列表](企业端/商品库.yaml) | 搜索 | 列表 | 走过 · 10-15 | （出用例时填） |
| 商品库 | 商品列表 | 翻页 | 列表 | 没走：只有 1 条数据，翻不了页 | |
| 商品库 | 新建商品 | 新建 | 表单 | 读了字段没提交：会占免费额度 | |
| 合格证 | 开具合格证 | 开具 | 表单 | 没走：禁点清单命中 | |
| 系统设置 | — | — | — | 没走：只读了骨架 | |
```

「用例」那一列由 `/qa-3-出用例` 填。

## 每个页面走到什么程度

| 类型 | 走到哪 |
| --- | --- |
| 列表 | 搜索、筛选、翻页、排序、看详情 —— **只读的都做** |
| 表单 | 打开，读字段：哪些必填、格式提示、有哪些选项。**不提交**，除非下面那条允许 |
| 弹层、抽屉 | 打开读完再关掉。**弹层挂在页面主体外面，地址也不变**，读整页 |
| 删除、作废、签发 | 记录入口在，不点 |

**要造数据才能走下去的**（核心流程常常要）：只在 `项目适配.md` 写明了"测试账号可以造数据"、
而且额度够的时候做，数据名字带 `QA测试`，做了几条写进副作用记录。
不满足就走到提交按钮前停下，覆盖表写「读了字段没提交：原因」，交给用户定。

## 控制成本

**token 的大头不在看页面，在对话太长。** 一屏只取可交互元素约 60 token，
但对话每多一轮，前面的全部内容都要再读一遍。所以：

- **全部走完时，一个模块一个对话。** 走完一个模块，更新覆盖表，告诉用户：
  「商品库走完了，建议开一个新对话打 `/qa-2-走一遍页面` 说继续走没走的」。进度在覆盖表里，不会丢
- **一次读一批，少来回。** 一个模块的几个页面，能用脚本一次走完、把读到的存成文件，就不要一页聊一轮
- 侧边栏、顶栏这种每页都一样的东西，**读一次就够**，后面的页面说"同上"
- 记录页面结构是机械活。用的工具能换便宜点的模型，可以提醒用户这一步能换，出用例和判定再用强的

## 接着走

覆盖表已经有了：

| 用户说 | 走什么 |
| --- | --- |
| 「继续走没走的」 | 覆盖表里「没走」和「走了一半」的，按表里的顺序 |
| 「走商品库」 | 只走这个模块 |
| 「全部走完」 | 所有没走的，一个模块一个对话（见上） |
| 「页面改版了，重走 XX」 | 重走这个模块，覆盖表里这个模块的「走了没」更新日期，**用例那列先不动**，交给 `/qa-3-出用例` 核对 |

## 边走边说

每走完一个页面，报一句：走到哪了、看到了什么、有没有记下可疑的。
**不要闷头走完一个模块才开口**——用户不知道你在干什么，就没法叫停。

## 硬约束

1. **读无障碍树，不要截图。** 同一屏（1440x900）实测：

   | 读法 | 约耗 token |
   | --- | --- |
   | 截图 | 1700 |
   | 无障碍树全量 | 470 |
   | 纯文字 | 150 |
   | **只取可交互元素** | **60** |

   **默认只取可交互元素和可见文字**，丢掉布局容器；看不明白再读全量。
   截图是最后手段，只在"样式错位、图片没加载、颜色不对"这类非看图不可时用。
   功能对不对，无障碍树里全都有，而且比看图准 —— 模型看图会认错字，读文字不会。

2. **命中禁点清单的元素：记录它存在，不要点。**

3. **限深**：一个页面往里最深 5 层。遇到记过的页面就回退。
   不限总步数 —— 全覆盖本来就要走很多步，靠「一个模块一个对话」控制，不靠砍步数

4. **不要乱造数据。** 空列表页如实记成 `空状态，没走进去`。
   要造数据才能走的，按上面「每个页面走到什么程度」那条办

5. **要输入时只用 `测试数据/固定数据.json` 里的值**，不许自己编。

6. **有多个系统时，一个系统一个系统地走**，写进 `地图/<系统>/`，
   各自对照 `02-禁点清单.md` 里该系统那一段。不要从一个系统顺着链接走进另一个系统。

7. **每一步操作之前，先确认当前在哪一页。** 点之前先读一眼当前页面的标题或地址，
   不要假设"上一步点完就一定到了那一页"。假设错了就会点空，然后开始怀疑页面有问题。

8. **`notes` 里记的怀疑，先换一种方式核实一次。** 读取工具的显示可能不全：
   比如它说"链接没有名字"，去看一眼元素里的文字；说"数字对不上"，先看清标签是不是同一个口径。
   核实不了就写成「怀疑」，并写上怎么核实的。

9. **不汇总别人的个人信息。** 页面上看到别人的 IP、手机号、邮箱：记下"这个页面显示了 XX"，
   **不要去收集、统计、导出这些值**，哪怕是为了证明这是个 bug。

## 走完要证明自己改了什么、没改什么

**走之前记下几个关键数字（列表条数、额度用量），走完再数一遍，把两次的数字都报出来。**
没造数据的，两次应该一样；造了数据的，差几条就该是你造的那几条。

## 输出 `地图/<系统>/<模块>.yaml`

文件头必须写明**用哪个账号、什么环境、哪天**走的。
**不同账号看到的入口不一样** —— 同一个站，游客能看到的菜单，专用账号可能没有。
不标清楚，这份地图被拿去跑另一个账号时就会扑空。

```yaml
模块: 优惠券
时间: 2026-09-20T14:30
环境: 生产 https://xxx.com
角色: 企业用户（测试数据/登录态/企业用户.json，显示名「沫」）
起点: /dashboard

页面:
  个人中心:
    路径: /profile
    可点的:
      - { 名称: 卡券包,   类型: link }
      - { 名称: 注销账户, 类型: button, 状态: 禁点清单命中·没点 }
    跳转:
      卡券包: 优惠券列表
    notes: []

没走到的:
  - 页面: 优惠券详情
    原因: 要点「立即使用」，会进下单流程，超出本模块范围
```

## 顺手填 `绑定/`

走的过程中把"这个页面从哪进、这个弹层怎么打开"记进 `绑定/`。
这一层是**业务语言到页面位置的对照**，界面改了只动它。

`用例/` 里的业务步骤怎么对到这些位置，是第 4 步跑测试时的事，这里只记位置。

## 必须停下来报告

- 出现禁点清单之外、但明显危险的操作（付款、发送、注销、删除全部）
- 连续 3 步没发现新页面
- 跳到登录页 —— **别去手动登录**，说明登录态失效了，停下来说
- 页面崩溃或白屏 —— 这是发现，写进 `notes` 继续走

## 走不通必须上报，不准自己换路

计划走 A，A 走不通时：

```yaml
走不通:
  - 计划: 从「个人中心」点「卡券包」
    实际: 「卡券包」不存在
    看到的: [订单, 设置, 帮助]
```

**静默绕过是这套流程里最危险的行为。走不通本身就是信息。**

## 收尾前：检查要不要写进 `项目适配.md`

逐条过一遍。**有任何一条，就必须写进「踩过的坑」**（做法 / 为什么 / 日期）：

- 换过等待方式（比如这个站不能等网络完全安静）
- 调整过并发（比如只能一个浏览器跑）
- 登录方式跟记录的不一样，或者多用了一个账号
- 为了跑通，改过配置文件
- 撤回过误报，而误报的原因是这个项目特有的
- 某种元素只能用特殊的方式找到
- 某个模块走一遍实际花了多久（下次估时间用）

收尾汇报里**必须有一行**：`项目适配.md：补了 N 条（逐条列出）` 或 `项目适配.md：这次没补`。
不能只靠自觉——写没写，要让用户一眼看得到。

## 提到的文件和编号，都写成能点开的链接

谁也记不住 `问题-07`、`已知-05` 底下是什么内容。所以：

- **对话里**：提到文件就写成 `[问题-07](报告/2026-10-10/疑似问题/问题-07.md)`，路径从项目根目录算
- **写进文档里的**（报告、变更单、用例清单、已知 bug、问题单、覆盖表）：每个编号、每个证据文件都写成链接，
  路径从**这份文档所在的目录**算（变更单在 `报告/2026-10-12/` 下，链 10-10 的问题单就写 `../2026-10-10/疑似问题/问题-07.md`）
- 编号链到它的出处：用例 → 那条用例所在的 yaml；问题 → 它的问题单；已知 → `校准/已知bug.md`
- **写完把每个链接对一遍文件在不在**。断掉的链接比没有链接更误导人
- 回放这种点开要下载的，链接旁边照样写上打开它的命令

## 对话长了、被压缩了怎么办

**进度随时落到文件里**：每走完一个功能点，就写进 `地图/覆盖表.md` 和那个模块的地图，不要攒到最后一起写。
这样不管是工具自动压缩对话、断网，还是用户中途关掉，都不会白做。

**发现对话被压缩过**（对话开头变成了一段摘要）：**先重读再继续** —— 这个 skill 的说明、
`项目适配.md`、`提示词/02-禁点清单.md`，还有记进度的那个文件。不要凭摘要里的印象往下走，
摘要里不一定还留着禁点清单的每一条。

**这一轮对话已经很长**（走完了一个模块、跑了十几条用例、来回几十轮）：收尾时提醒一句
「下一个命令可以在新对话里打，进度都在文件里」。开新对话比压缩好：压缩留下什么你控制不了，
新对话从文件里读，什么都不会丢。对话不长就不用提。

## 收尾：照这个格式报，一条都不能少

1. **这一步动了哪些文件**：按目录分组，新增还是修改，每个一句话
2. **没动哪些**：列出来，让用户确认你没碰别的
3. **现在去看哪个文件**：一般是 `地图/覆盖表.md`
4. **这轮读了几屏、用的哪种读法、大约多少 token**
5. `项目适配.md`：补了 N 条（逐条列出）或 这次没补
6. **下一步打哪个命令**

这一步额外要说：
- **覆盖到哪了**：几个模块走完、几个走了一半、几个没走；这次走的是核心流程、全部还是指定模块
- **没走完的，以后怎么接着走**（给出那句话）
- 走了几个页面、`notes` 里记了几条怀疑（已核实几条、没核实几条）、
  哪些没走到以及为什么、走之前走之后的关键数字一不一样

**收尾时把这几条念给用户听**，让他知道该挑什么毛病（他不会挑，就只能信你说的）：

- 打开 `地图/覆盖表.md`：每一格是不是都有状态，「没走」的有没有原因
- 打开 `地图/` 下刚写的 yaml：文件头有没有写账号、环境、日期
- notes 是不是分了"已核实"和"没核实"，有没有直接下结论说是 bug
- 全文搜一下 `div`、`.`、`//`：地图里不该出现任何选择器

说完**停下**。下一步是 `/qa-3-出用例`，它只给走过的部分出用例。
**不要自己开始判对错、写问题清单** —— 那是后面的事。

## 老项目缺文件时

项目是旧版建的、缺了这一步要读的某个文件：**按没有它的方式照常做，不要报错停下**。
做完最后提一句：「新版多了 XX，可以跑一次 `/qa-1-建目录` 补上」。

**老项目没有覆盖表**：按已有的地图补一张，走过的标「走过」，地图里「没走到的」照抄原因，
