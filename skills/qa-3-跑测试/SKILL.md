# 第 3 步 · 跑一轮，出报告

## 先绑定，再执行

`cases/` 里的步骤是业务语言（"进入购物车"），`maps/` 里是真实路径。
先把两边对上，写进 `bindings/`：

```yaml
"进入购物车": 首页 → 点击"购物车"角标
"选择该券":   提交订单页 → 优惠券行 → 列表中匹配"满100减20"
```

**界面改了只改这一层，`cases/` 一个字都不动。**

## 判定三档，不是两档

| 判定 | 什么时候用 |
| --- | --- |
| `通过` | 符合预期，**且你能指出依据** |
| `失败` | 违反了某条明确写下来的规则 |
| **`说不准`** | 规则没覆盖到 / 依据模糊 / 你也不确定 |

> **「说不准」不是失职，是最有价值的输出。硬着头皮下结论才是。**

一轮里 `说不准` 占 10~20% 是健康的。
接近 0 说明在硬判，超过 40% 说明 `cases/` 写得太含糊 —— 两种都要说出来。

## 判定必须带依据

不要只给结论。**人 review 的是依据，不是结论** —— 依据对不对一眼看得出来，结论对不对看不出来。

```json
{
  "id": "C-07",
  "规则": "PRD 3.2 · 订单满 100 元才能用满减券",
  "步骤": ["进入购物车（99 元）", "点去结算", "选「满100减20」"],
  "预期": "券置灰，提示还差 1 元",
  "实际": "券可选中，点击后弹「系统错误」",
  "判定": "失败",
  "依据": "PRD 3.2 写了门槛校验应在选择时拦截，这里没拦截且报了未定义错误",
  "证据": {
    "aria快照": "reports/2026-09-20/evidence/C-07.aria.yaml",
    "控制台": "TypeError: Cannot read properties of undefined (reading 'threshold')",
    "网络": "POST /api/coupon/apply → 500",
    "trace": "reports/2026-09-20/evidence/C-07.trace.zip"
  }
}
```

## 通用巡检（不需要 PRD，每轮都跑）

在走过的每个页面上验：

```
- 没有崩溃、白屏、错误页
- 控制台没有 error，网络没有 5xx
- 界面上不出现 undefined / null / NaN / [object Object]
- 返回键能回上一页，不卡死
- 关键数字自洽：总额 = 各分项之和
- 任意输入框塞 500 字符不崩
```

这层最划算：**答案不依赖需求，你自己就能判**，而且人最不爱干。

## ⚠️ 走不通必须上报，不准自己换路

用例第 3 步的按钮点不到时：

```json
{
  "判定": "说不准",
  "走不通": {
    "计划": "点商品详情页的「加入购物车」",
    "实际": "该按钮不存在",
    "看到的": ["立即购买", "收藏", "分享"],
    "我没做的事": "没有改用列表页的快捷加购"
  }
}
```

**你绕过去了，bug 就被埋了。** 这是整套流程里最容易犯、代价最大的错。

## 跨系统用例（`cases/` 里有 `谁:` 或 `对账:` 时）

**等待**：轮询到条件成立，不准固定 sleep。超过用例里写的时限就判失败 ——
时限到不了本身就是 bug，不是"环境慢"。

**上下游：流程走完不算通过，字段对账全部相等才算。**
按 `bindings/` 的「ID对照」串起链路，按「数据位置」逐字段取值比对。

**挂了必须报出断在哪一跳**，不能笼统说失败：

```json
{
  "判定": "失败",
  "断点": "第 2 跳：订单系统 → 财务系统",
  "已确认": "订单系统下单成功，orderNo 20260921-0043，接口 200",
  "未发生": "财务系统 60 秒内查不到 outNo=20260921-0043",
  "还没查的": "消息有没有投递 / 是不是被过滤条件挡了"
}
```

跨系统的 `说不准` 比例会明显偏高 —— 边界上谁的锅本来就不清楚。
这是正常形态，在报告里说明，不要为了压比例硬判。

## 输出

```
reports/2026-09-20/
├─ report.md       # 人看的汇总
├─ findings/       # 疑似问题，等人确认 ← 失败和说不准都落这儿
│  └─ F-01.json
└─ evidence/       # 快照、trace、控制台
```

`findings/` 里的**还不是 bug，是疑似**。人确认后才 `/qa-4-提bug`。

## 最后提醒一句

报告结尾附上：

> 绿灯 ≠ 能发版，红灯 = 一定不能发版。
> 这轮跑的是 `cases/` 里的 N 条 + 通用巡检，没覆盖的部分见 `calibration/known-bugs.yaml` 的缺口清单。
