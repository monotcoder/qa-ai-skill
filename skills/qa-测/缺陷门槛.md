# 缺陷门槛：只报肯定是缺陷的

`/qa-测` 扫页面、补用例、回归时判「失败」、写问题单之前，都要过这一关。

真实用户的反馈：报上来的大多不是问题——**要么早就说清楚了，要么他根本不认为是问题**。
报十条错一半，他就不看了，真 bug 也跟着被忽略。所以宁可少报，报出来的必须站得住。

**一轮报 0 个缺陷是正常的。不准为了显得有产出凑数。**

## 第一关：说过了的，不报

问题单写之前，先对这几处，**命中任何一处就不报**：

| 查哪里 | 命中了怎么办 |
| --- | --- |
| `校准/已知bug.md` | 是已知的，不是新问题。脚本里那条应该已经标了已知失败，没标就补上 |
| `校准/不算bug.md` | 用户说过不算。**同一类的也不报**：他说过「叫法不一致不算」，别的叫法不一致也不算 |
| 以前的 `报告/*/疑似问题/` 里写着「用户确认不是 bug」的 | 同上。顺手把它补进 `校准/不算bug.md`，以后查一处就够 |
| 用例的预期来源是 `用户确认`，系统行为跟他确认的一样 | 不报。他确认过就是这样 |
| PRD、产品说明里明写就是这样的 | 不报。哪怕你觉得设计得不好 |
| `项目适配.md` 里写着的环境限制、项目约定（比如测试环境不发短信） | 不报 |

## 第二关：必须是"肯定"

下面四条**全部满足**才算缺陷，少一条就不是：

1. **违反的规则能指出原文**：PRD 第几条 / 产品说明的原话 / 用户确认过的预期（带日期）/ 下面「硬规律」里的一条。
   说不出原文的，不是缺陷。**预期来源是 `基线` 的，挂了只是「变了」，不是缺陷**，见下面「基线挂了」
2. **核实过一次**：脚本断言没过之后，换一种方式再看一次（口径是不是同一个、接口有没有返回、读取工具是不是看漏了），
   见 `回归.md` 的「下结论之前，先核实一次」
3. **不是环境、数据、权限引起的**：登录态过期、代理、测试账号没权限、测试数据被别人改了，都不算
4. **写得出开发照着点就能复现的步骤**。写不出来，说明你自己也没弄清

## 硬规律：不用等谁确认，违反了就是缺陷

- 崩溃、白屏、错误页、App 闪退
- 接口返回 5xx
- 界面上出现 `undefined`、`null`、`NaN`、`[object Object]`、没替换掉的 `{{变量}}`
- 写进去读不回来：提示保存成功，列表或详情里没有，或者值变了
- 看到、改到别的账号、别的租户的数据
- 重复点提交，生成了两条
- 必填项不填也保存成功了
- **同一个口径**的数字对不上：列表写共 12 条，实际 11 条（口径先核对，见第二关第 2 条）
- 按钮、链接点了没反应，或者去了跟它名字明显不符的地方
- 用户看得到的入口，按产品说明走，走不到产品说明里说的结果

## 不报的，就算你觉得不对

这些**不写问题单、不进报告的「要你定的」、不进审核表的「是不是 bug」**：

- 叫法不一致（列表叫「已上架」，筛选叫「已发布」）、文案、措辞、标点
- 样式、排版、颜色、对齐、图标
- 体验建议：「这里最好加个提示」「这个按钮应该放上面」
- 性能感受（「有点慢」）。用例里写了时限、超了的除外
- 控制台的 warning；控制台有 error 但功能是好的
- 没有任何文档说要有、你觉得应该有的功能
- 只在你那一种读法下出现、换个方式就核实不了的

用户在 `项目适配.md` 里写了「也要看建议」「错别字也要报」的，照他说的：
**放在报告最后一段「顺便看到的」，一条一行，不写问题单、不编号**，他想提再说。

## 基线挂了：只报变化，不报 bug

没有原文依据的行为（产品自己的规则，没写在哪），扫的时候按**系统当时的样子**写成断言，预期来源标 `基线`。
它只能说明"跟上次一样"，**说明不了对不对**。所以：

- 扫的时候：基线是照现状写的，不会挂，也**不会因为它报任何东西**
- 以后跑挂了：说明这里变了。**不写问题单**，报告里一行「变了」，审核表「变了，变得对不对」那一段问一句
- 用户说变得对 → 断言改成新的样子，预期来源改 `用户确认`；说变错了 → 这时才算缺陷（有了用户确认），进已知 bug

老项目里预期来源还是 `AI推测` 的，一样处理：对不上不是缺陷，进审核表问。

## 判下来是什么，写到哪

| 结果 | 写到哪 |
| --- | --- |
| 过了两关，是缺陷 | 问题单 `问题-xx.md`；脚本那条标 `问题-xx 待确认`（见 `写脚本.md` 的「脚本里的标记」）；进审核表「是不是 bug」 |
| 第一关命中已知 bug | 不另起问题，报告里一句「已知-xx 还没修」 |
| 第一关命中不算 bug | 不报，报告「其他」里数一下挡掉了几条、哪几类。脚本的断言要是还按"会报错"写的，改成用户说的样子 |
| 基线（或老的 AI推测）挂了 | 不写问题单。审核表「变了，变得对不对」；脚本标 `变了`；最近判定写 `变了 · <日期>` |
| 第二关不满足（说不出原文、核实不了） | 判 `说不准`，报告里一句话写清卡在哪。**不写问题单** |
