# 平台 · 安卓 App

第 1 问答「安卓 App」时读这个文件。Web 读 `平台-web.md`，小程序读 `平台-小程序.md`。

这个文件只讲**六件和平台有关的事**：怎么连上、怎么看界面、怎么定位、怎么知道现在在哪一屏、
登录态怎么办、证据怎么留。剩下的（建目录、出用例、判定三档、提 bug、存脚本）和 Web 完全一样，
正文怎么写就怎么做。

## 一、怎么连上

靠 `adb`，不需要在被测 App 里埋任何东西。

| 要什么 | 怎么查有没有 | 没有怎么办 |
| --- | --- | --- |
| adb | `adb version` 能出版本号 | 装 Android 平台工具。Mac 上装了 Android Studio 的，一般在 `~/Library/Android/sdk/platform-tools/`，把这个目录加进 PATH |
| 一台设备 | `adb devices` 能列出设备，状态是 `device` | 见下面「设备从哪来」 |
| 安装包 | 用户给 apk 路径，或者他自己在设备上装好 | 问用户要 |

连上之后固定用**同一台**设备，设备号写进 `项目适配.md`。多台设备同时连着时，每条命令都要带
`adb -s <设备号>`，不带的话 adb 会报错或者选错设备。

```bash
adb devices                      # 列出设备，确认只有一台、状态是 device
adb -s emulator-5554 shell echo ok
```

### 设备从哪来

| | 好处 | 代价 |
| --- | --- | --- |
| **真机**（推荐） | 这才是用户真实的样子：性能、推送、相册、权限弹窗都真 | 要插线或连无线调试，要在设备上点「允许 USB 调试」 |
| 模拟器 | 不占手机，随便清数据，可以同时开几台 | 摄像头、推送、支付、指纹都不真；**偶尔整个画面会卡死**（截出来全白或全黑），这时重启模拟器，别去怀疑 App |

第一次连真机，设备上会弹「是否允许 USB 调试」，**必须用户自己点**，AI 点不了。提前告诉他要点一下。

## 二、怎么看界面：读结构，不要截图

和 Web 一样，**默认读界面结构，不截图**。安卓上读结构的等价物是 uiautomator 导出的界面树：

```bash
adb shell uiautomator dump /sdcard/u.xml
adb shell cat /sdcard/u.xml
```

导出来的是 XML，一个节点一行，带 `text`、`content-desc`、`resource-id`、`bounds`。
只取有 `text` 或 `content-desc` 的节点，丢掉纯布局容器，token 和 Web 读可交互元素是一个量级。
**截图是最后手段**，只在"样式错位、图片没加载、颜色不对"这类非看图不可时用。

### 读不到和看不见，是两件不同的事

这两种情况在安卓上很常见，**分不清就会把工具的问题当成 App 的 bug**：

| 现象 | 多半是什么 | 怎么确认 |
| --- | --- | --- |
| 截图全黑、文件 0 字节 | App 开了防截屏（`FLAG_SECURE`），隐私类、支付类 App 很常见。**这是功能，不是 bug** | 界面树照样导得出来。用界面树继续走，证据里写明"此页防截屏，无法截图" |
| 截图全白、连状态栏都没有 | 模拟器画面卡死了，和 App 无关 | 回桌面再截一张，还是白的就重启模拟器 |
| 界面树是空的 / 只有一个节点 | 当前是别的应用的窗口（权限弹窗、输入法），或者页面还在加载 | 先确认当前在哪一屏（见第四节），等一下再导一次 |

### 弹窗是另一个窗口

系统权限弹窗、分享面板、输入法，都**不属于被测 App**。界面树里能看到它们，但它们的按钮文案随系统版本变。
处理权限弹窗最稳的办法是在跑之前直接授权，别去点：

```bash
adb shell pm grant <包名> android.permission.READ_MEDIA_IMAGES
```

哪些权限要预先授、哪些要留着手工点一次（因为"第一次打开要不要弹权限"本身就是要测的），
写进 `项目适配.md`。

## 三、怎么定位一个元素

按这个优先级，越靠前越稳：

| 用什么 | 例子 | 什么时候会失效 |
| --- | --- | --- |
| `resource-id` | `com.xx.app:id/btn_submit` | 开发改了 id（少见）；混淆一般不动它 |
| `content-desc` | `提交订单` | 无障碍描述被改 |
| `text` | `提交` | **文案一改就失效**，多语言下必失效 |
| 坐标 | `(540, 1680)` | **换分辨率、换机型、转屏就全废**，只在前三种都没有时用，并在用例里写明 |

和 Web 的规矩一样：**这些定位信息只能写进 `绑定/`，`用例/` 里一个都不许出现**。
安卓这边更要守，因为坐标特别容易被顺手写进用例，然后换一台机器全军覆没。

## 四、怎么知道现在在哪一屏

Web 看地址栏，安卓看当前 Activity：

```bash
adb shell dumpsys window | grep mCurrentFocus
```

每一步操作之前先确认在哪一屏，不要假设"上一步点完就一定到了那一屏"。
假设错了就会点空，然后开始怀疑 App 有问题。

地图 yaml 里的"路径"这一栏，安卓填 **Activity 名 + 界面标题**，没有 URL 这回事：

```yaml
页面:
  我的空间:
    路径: com.xx.app/.MainActivity · 标题「我的空间」
    可点的:
      - { 名称: 设置,   类型: button, id: com.xx.app:id/nav_setting }
      - { 名称: 清空数据, 类型: button, 状态: 禁点清单命中·没点 }
```

## 五、登录态

Web 把登录态存成文件，用完一份换一份。**安卓不行：登录态在设备上，一台设备同时只能登一个账号。**

所以：

- 一个角色跑完再换下一个，换的时候在 App 里退出登录重登，**顺序写进用例**
- 有多个角色要同时在线的（买家下单、后台审核），**要两台设备**（两个模拟器也行），
  一台一个角色，设备号和角色的对应关系写进 `项目适配.md`
- **`pm clear` 会把登录态连同所有数据一起清掉**。清之前想清楚：这台设备上攒的测试数据也没了
- 密码一律让用户自己在设备上登一次，**不要替用户输密码**，也不要把密码写进任何文件

## 六、证据怎么留

| 要什么 | 命令 | 注意 |
| --- | --- | --- |
| 截图 | `adb exec-out screencap -p > 证据/xx.png` | 防截屏的页面截出来是 0 字节，改用界面树 |
| 界面树 | `adb shell uiautomator dump /sdcard/u.xml && adb shell cat /sdcard/u.xml` | 防截屏也照样能导 |
| 录屏 | `adb shell screenrecord --time-limit 30 /sdcard/x.mp4` | 有时长上限；**模拟器上经常直接失败**，失败就改成连续截图 |
| 日志 | `adb logcat -d > 证据/xx.log`；崩溃看 `adb logcat -b crash` | 跑之前先 `adb logcat -c` 清一次，日志才对得上这一条用例 |

**报崩溃必须带 `-b crash` 的那一段**，这是安卓上最硬的证据，开发一看就知道在哪一行。

日志里有别人的手机号、IP 这类信息时，和 Web 一样：记下"日志里出现了 XX"，不要整段原样贴进报告。

## 七、存成脚本用什么

读界面、找元素只要 adb 加界面树。但扫页面的时候就要**当场把用例存成脚本**，
所以**第一次扫之前**就要选好一个、装好（缺什么一次列给用户，他点头才装）：

| 工具 | 适合 | 代价 |
| --- | --- | --- |
| **maestro**（推荐） | 流程用 YAML 写，和 `用例/` 里的业务语言几乎一一对应，学员看得懂 | 复杂断言不如 Appium 全 |
| Appium | 什么都能做，老团队多半已经在用 | 装起来重，环境问题多 |
| 项目里已经有的 | **直接用它** | —— |

规矩和 Web 一样：**项目里已经在用什么，就用什么，不要替用户换掉。**
选了哪个、为什么，写进 `项目适配.md` 的「工具」那一段。

## 八、安卓特有的坑，提前说给用户

这几条第一次跑就会遇到，提前说一句，省得用户以为是 App 坏了：

- **输入中文**：`adb shell input text` 只认 ASCII，中文会变成空白。要输中文得装一个输入法工具，
  或者改用剪贴板。实测结论写进 `项目适配.md`
- **输入太快会丢字符**：App 刚启动、界面还在动画时发的点击和输入，会被整个吞掉。
  每一步之前确认在哪一屏（第四节），比加 `sleep` 可靠
- **机型差异**：同一个 App 在不同厂商的系统上，权限弹窗、返回手势、后台杀进程策略都不一样。
  报 bug 时**必须写清机型和系统版本**，不然开发复现不了
- **转屏和分屏**：横屏、分屏下布局会变，坐标全废。要测就单独列成用例

## 九、禁点清单在安卓上要多问几条

除了付款、发短信这些，安卓上还要问：

- 会不会触发**真实的推送**给真人
- 会不会**真的打电话、发短信**（测试机插了真卡的话）
- 有没有「清除数据」「注销账号」「卸载」这类一按就回不去的入口
- 改系统设置的（默认应用、无障碍权限、电池优化），改完会影响后面所有用例
