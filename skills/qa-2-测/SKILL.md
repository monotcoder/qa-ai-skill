# 第 2 步 · 测：先报计划，说「开始」才动

## 开口第一行：报版本

开始做之前，**第一行单独写**：

```
QA 流水线 v1.8.0 · qa-2-测
```

就这一行，不加别的话，像软件标题栏那样。直接写出来，不用放进代码块。
版本号就是这个文件开头那行注释里的 `version`，**不要去磁盘上读文件来报** ——
你报的必须是你现在加载的这一份。学员出问题时，作者靠这一行知道他跑的是哪一版。

接着顺手比一下（找得到就比，找不到就跳过，不要卡住）：

- skill 目录里 `qa-更新/版本.json` 的版本比你报的新 → 这个对话加载的是旧版。
  告诉用户「skill 已经更新了，但这个对话还在用旧版，请重启 AI 工具或者开一个新对话，再打这个命令」。
  他说「继续」，就照你现在这一版接着做，不要拦着
- 项目里 `.qa-ai.json` 的版本比你报的新 → 这个项目是更新的版本建的，提醒他先打 `/qa-更新`

这一次新写或改过的文档（地图、覆盖表、用例清单、审核表、报告、问题单），标题下面写一行
`生成：QA 流水线 v1.8.0 · qa-2-测 · <日期>`。改已有的文档，把这一行改成这一次的。

## 这个文件管什么

**只管"这次做哪几件、按什么顺序、先让他点头"。** 每件事怎么做，写在同目录的分文件里，**做到哪件才读哪份**，
不要一开始全读进来——那是白花 token。

| 这件事 | 读哪份 |
| --- | --- |
| 扫页面，边扫边写用例和脚本 | `扫页面.md` |
| 照 PRD、新需求补用例；把基线升级成有依据的 | `补用例.md` |
| 回归：跑存好的脚本，出报告 | `回归.md` |

三份规矩，**写用例、写脚本、判挂了的时候**才读：`写用例.md`、`写脚本.md`、`缺陷门槛.md`。
要他定的怎么写进审核表，照 `qa-3-审完了` 那个 skill 目录里的 `审核表.md`。

## 1. 先看项目开始过没有

项目根目录**没有 `.qa-ai.json`** → **停下，什么都不建**，只说一句：
「这个项目还没开始过，先打 `/qa-1-开始`：它会建好测试目录、跑通登录、读出整个站有哪些模块，然后再回来打 `/qa-2-测`。」

**有 `.qa-ai.json`**，看缺不缺东西：

- 缺 `提示词/02-禁点清单.md` → **停下来问**，不要凭感觉判断什么能点
- 缺 `项目适配.md` → 按同目录的 `项目适配模板.md` 当场建一个，建完告诉他。只建这一个，别的不动
- 缺别的文件 → 按没有它的方式照常做，不要报错停下，收尾提一句「新版多了 XX，打一次 `/qa-1-开始` 就补上」
- 目录还是英文名的（`cases/`、`maps/` 这些）→ 按同目录的 `目录对照.md` 找对应的英文目录，照常做，**不要新建中文目录**。
  收尾提一句「打一次 `/qa-1-开始` 可以改成中文目录」

## 2. 每次都先读的

1. `.qa-ai.json` 的 `端`（没有就按 `Web`），再读同目录对应的平台文件：`平台-web.md`、`平台-安卓.md`、`平台-小程序.md`。
   "怎么连上、怎么看界面、怎么定位、登录态在哪、证据怎么留、脚本用什么写"全在那里
2. `项目适配.md`：这个项目的做法和踩过的坑
3. `提示词/02-禁点清单.md`
4. `用例/用例清单.md`、`地图/覆盖表.md`、`用例/审核表.md`：**进度全在这几份里，不靠聊天记录**
5. `校准/已知bug.md`、`校准/不算bug.md`：有就读，没有就算了

这一步只读文件，**不打开被测系统，不跑任何东西**。

## 3. 定这次做哪几件

按他说的，加上项目现在的状态：

| 他说的 | 这次做 |
| --- | --- |
| 「跑一轮」「回归」「XX 修好了再跑一下」「跑批次-02」 | 回归 |
| 「扫一遍」「先扫核心流程」「全部扫完」「继续扫没扫的」「扫商品库」「页面改版了重扫 XX」 | 扫页面 |
| 给了 PRD、需求文档，或者说「有 PRD 了」「这个新功能怎么测」 | 补用例 |

**只打了 `/qa-2-测`、什么都没说的**，按项目状态提一个建议：

| 项目状态 | 建议做 |
| --- | --- |
| 覆盖表里还一个都没扫（刚 `/qa-1-开始` 完） | 扫页面：先扫核心流程（`/qa-1-开始` 收尾时建议过哪条，就是哪条） |
| 有存好的脚本 | 回归全部存好的。覆盖表里还有没扫的，列进「这次不做」 |
| 项目里有新放进来的 PRD、需求文档，还没照它补过用例 | 加上补用例 |

**几件都要做时，顺序是：回归 → 补用例 → 扫页面。** 回归最快，先知道现在是什么状态；
扫页面最慢，放最后，他看完前面的结果可以喊停。

## 4. 先给他看计划，他说「开始」才动

**动手之前，把计划写成一张小表给他看，然后停下等他回话。** 不管他说得多清楚、这次多小，都先给他看。

```markdown
这次打算做：

| 做什么 | 范围 | 大概多久 | 会不会动数据 |
| --- | --- | --- | --- |
| 回归 | 已存的 23 条（商品库、批次发布、扫码追溯） | 5 分钟 | 不写数据。扫码量会 +3，见副作用记录 |
| 扫页面 | 合格证模块，4 个页面 | 20 分钟 | 只读，表单不提交 |

这次不做：
- 系统设置等 8 个模块还没扫
- 批次-05「删除批次」：范围是全量，会真删数据，要跑你说一声

登录：用 凭证.env 里「企业用户」那个账号，脚本自己登。

说「开始」我就动手；要删哪项、改范围，直接说。
```

几条规矩：

- **「会不会动数据」每一行都要写**，写实话：只读、会造几条带 `QA测试` 的数据、计数会 +N、会发通知……
  不知道会不会，就写「不知道，第一次扫，碰到提交按钮前会停」
- 会留痕迹的（`范围: 全量`）、要他准备数据的（`范围: 要用户准备`）、禁点清单命中的，**默认放进「这次不做」**，他点名了才做
- 要他手动登录的（验证码、扫码），在「登录」那一行写清楚，并说什么时候要他登
- 时间估不准就说粗估，按覆盖表和上次的用时估
- 他说「开始」「行」「可以」「跑吧」都算点头；他改了范围，按改后的再报一遍表，再等他点头
- **他没回话之前，不打开被测系统、不跑脚本、不写任何文件**

## 5. 做的时候

做完一件，**落好文件再做下一件**：回归的报告和用例清单、扫完一个模块的覆盖表和脚本。
每做完一件报一句结果，不要闷头做完全部才开口。

**只做表里那几件。** 做的过程中发现计划外的事（比如回归时发现还有个模块没扫、要造数据才能往下扫），
**记下来放进收尾，不顺手做**。中途要碰会写数据、会留痕迹的，而计划里没写的，停下来问。

不管做哪件都一样的：

- **只报过了 `缺陷门槛.md` 的**。没原文的写 `基线`，挂了只说「变了」。一轮报 0 个是正常的，不准凑数
- **要他定的只写进审核表**，不在对话里一条条问。几件事做下来要他定的，**合成一批**写进去
- **禁点清单是第一优先级**，扫的时候不点，脚本里也不点
- **走不通必须上报，不准自己换路**。绕过去了，bug 就被埋了
- **判定三档**：通过 / 失败 / 说不准。基线过了叫「没变」，挂了叫「变了」，都单独数
- **登录**：账号密码登录的，过期了脚本自己重登，不用问他；重登失败、要验证码的，停下来说。
  **你自己不在页面上输账号密码**，也不打开 `凭证.env`

## 提到的文件和编号，都写成能点开的链接

谁也记不住 `问题-07`、`已知-05` 底下是什么内容。所以：

- **对话里**：提到文件就写成 `[问题-07](报告/2026-10-10/疑似问题/问题-07.md)`，路径从项目根目录算
- **写进文档里的**（覆盖表、用例清单、审核表、报告、问题单）：每个编号、每个证据文件都写成链接，
  路径从**这份文档所在的目录**算（报告在 `报告/2026-10-12/` 下，链 10-10 的问题单就写 `../2026-10-10/疑似问题/问题-07.md`）
- 编号链到它的出处：用例 → 那条用例所在的 yaml；问题 → 它的问题单；已知 → `校准/已知bug.md`
- **写完把每个链接对一遍文件在不在**。断掉的链接比没有链接更误导人
- 回放这种点开要下载的，链接旁边照样写上打开它的命令

## 对话长了、被压缩了怎么办

**进度随时落到文件里**：扫完一个模块、跑完一条用例，就把覆盖表、用例清单、报告写好，不要攒到最后一起写。
这样不管是工具自动压缩对话、断网，还是用户中途关掉，都不会白做。

**发现对话被压缩过**（对话开头变成了一段摘要）：**先重读再继续** —— 这个文件、正在做的那件事的分文件、
`项目适配.md`、`提示词/02-禁点清单.md`，还有记进度的那几份。不要凭摘要里的印象往下走，
摘要里不一定还留着禁点清单的每一条，也不一定还留着他点头的是哪几件。

**这一轮对话已经很长**（扫完了一个模块、跑了十几条用例、来回几十轮）：收尾时提醒一句
「下次可以在新对话里打 `/qa-2-测`，进度都在文件里」。对话不长就不用提。

## 收尾前：检查要不要写进 `项目适配.md`

逐条过一遍。**有任何一条，就必须写进「踩过的坑」**（做法 / 为什么 / 日期）：

- 换过等待方式（比如这个站不能等网络完全安静）
- 调整过并发（比如只能一个浏览器跑）
- 登录方式跟记录的不一样，或者多用了一个账号；登录态实际多久过期
- 为了跑通，改过配置文件
- 撤回过误报，而误报的原因是这个项目特有的
- 某种元素只能用特殊的方式找到
- 定下了写脚本的工具，或者装了什么
- 某个模块扫一遍实际花了多久（下次估时间用）
- 这个项目的规则写在哪（PRD 在哪、产品说明在哪）
- 有些流程只能在某个账号或某个环境下测；某个流程有不可逆的步骤，测完要手工清理
- 量出来的副作用结论（什么计数、什么不计）

收尾汇报里**必须有一行**：`项目适配.md：补了 N 条（逐条列出）` 或 `项目适配.md：这次没补`。

## 收尾：照这个格式报，一条都不能少

**第一句就是结果**，把这次做的几件合在一起说，比如：
「回归 23 条：通过 15、没变 6、失败 1、变了 1。新扫了合格证，存了 12 条脚本。要你定的 2 条。」

1. **这次动了哪些文件**：按目录分组，新增还是修改，每个一句话
2. **没动哪些**：列出来，让用户确认你没碰别的
3. **跟计划比**：计划里的每件做完没有；有没做完的，说为什么。**计划外的一件都没做**，发现了的列出来
4. **现在去看哪个文件**：有要他定的就是 `用例/审核表.md`；回归了就是这次的报告；都没有就是 `用例/用例清单.md`
5. **这轮读了几屏、用的哪种读法、脚本跑了几次、大约多少 token**
   token 只能估读页面那一部分，**报的时候说清这不是总数**：每多一轮对话，前面的内容都要重读一遍，
   整个对话的消耗通常是读页面的几十倍，以 AI 工具自己显示的用量为准。有副作用的操作做了几次，也在这一条报
6. `项目适配.md`：补了 N 条（逐条列出）或 这次没补
7. **下一步**：见下面

做了哪件，就加上那份分文件「收尾额外要说」和「收尾前自己查」里的内容。
**查的结果每条一句「过了」或「没过：原因」**，带上能点开的文件链接。你能查的事不要甩给用户去查，没过的能改就先改好再收尾。

有要他定的，**一句话指向审核表**，不在对话里列。说完**停下**，不要自己接着做下一件。

下一步只有这几种：

| 情况 | 下一步 |
| --- | --- |
| 审核表里有待审的 | 看完在这个对话里说「审完了」（你就读 `qa-3-审完了` 那个 skill 的 `SKILL.md` 照做）；换了新对话就打 `/qa-3-审完了` |
| 覆盖表还有没扫的 | 「想补就打 `/qa-2-测` 说继续扫没扫的」 |
| 没变的占大多数，而且他有 PRD 没给过 | 「把 PRD 放进项目，打 `/qa-2-测` 说有 PRD 了，这些没变的能升级成验过对错的」 |
| 都没有 | 什么都不用做，下次提测再打 `/qa-2-测` |

**不要自己去 bug 平台上提单。** 那是他说了「审完了」之后，`qa-3-审完了` 的事。

## 老项目：以前版本留下的

- 用例清单「脚本」列是 `未存`、`草稿` 的：做到这条时照 `写脚本.md` 补写或定稿，见 `回归.md`
- 预期来源是 `AI推测` 的：按 `基线` 对待，挂了只报变了
- 覆盖表里写「走过」的：当成「扫过」
- 老的审核表里还有「待审」的批次（1.7.0 以前那种逐条审用例的）：照 `补用例.md` 最后一节处理
- 登录还是"请用户手动登"的、而登录方式是账号密码：收尾提一句「现在可以把测试账号填进 `凭证.env`，脚本自己登，打一次 `/qa-1-开始` 就能改」
- **以前报的问题单还在 `待确认`、不在审核表里的**：用 `缺陷门槛.md` 重新过一遍。
  过了的，进这一次的审核表「是不是 bug」；没过的，问题单「平台」改 `不提`，加一句「按 1.7.0 缺陷门槛不再报：<原因>」，
  脚本上的 `问题-xx 待确认` 标记照 `写脚本.md` 改掉（基线的改成 `变了`，说不出原文的去掉标记、断言按现状写）。
  收尾报一句：老问题单重新过了几张、留下几张、不再报几张。**这件也写进计划表**，他点头了才做
