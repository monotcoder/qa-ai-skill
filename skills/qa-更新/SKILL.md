# 更新这套 skill

## 开口第一行：报版本

开始做之前，**第一行单独写**：

```
QA 流水线 v1.3.6 · qa-更新
```

就这一行，不加别的话，像软件标题栏那样。直接写出来，不用放进代码块。
版本号就是这个文件开头那行注释里的 `version`，**不要去磁盘上读文件来报** ——
你报的必须是你现在加载的这一份。学员出问题时，作者靠这一行知道他跑的是哪一版。

仓库有两个地址，**内容一样，每次发版两边同时推**：

| | 地址 | 不用 git 时查 tag 的地址 |
| --- | --- | --- |
| GitHub | https://github.com/monotcoder/qa-ai-skill | `https://api.github.com/repos/monotcoder/qa-ai-skill/tags` |
| Gitee（国内快） | https://gitee.com/notcoder/qa-ai-skill | `https://gitee.com/api/v5/repos/notcoder/qa-ai-skill/tags` |

用哪个：用户说了用哪个就用哪个。没说的，**先试 Gitee**（国内连 GitHub 常常很慢或者卡住），
等 10 秒左右没反应就换 GitHub。两个都连得上、版本号不一样的，用大的那个
（作者两边同时推，偶尔有一边慢一步）。用了哪个，跟用户说一声。

用户不懂命令行，全程你来做，每一步用大白话说你在干什么。

## 1. 找到 skill 目录

就是你读取 skill 的用户级目录。不确定就先查清楚，别猜。

## 2. 先查版本号，不用下载

- 本地：skill 目录里 `qa-更新/版本.json` 的 `版本`
- 最新：**只查仓库的 tag，不下载仓库**。有 git 就用 `git ls-remote --tags <仓库地址>`，
  没有 git 就读上面表里「查 tag 的地址」。取 `v` 开头、版本号最大的那个

**以 tag 为准，不以 main 分支为准。** main 上可能有作者还没发版的改动，那不该装到用户电脑上。

一样 → 告诉用户"已经是最新版"，结束。**什么都没下载，什么都不用删。**

查不到（两个地址都连不上）→ 直说连不上，不要猜版本号。开了代理的，命令行可能不走代理，先提醒他看一眼。

## 3. 有新版才下载，并先换成最新版的自己

把**最新那个 tag** 从第 2 步用的那个地址下载到一个临时目录（要带上所有 tag，第 6 步要用旧版对比）。

如果里面的 `skills/qa-更新/SKILL.md` 跟你现在读的这份不一样，
**停下，改为照新版那份执行。**

更新的逻辑本身也会改。用旧逻辑去装新版本，出了错没人能修。

## 4. 先讲清楚这次更新了什么，再动手

读临时目录里的 `更新说明.md`，**只挑本地版本之后的条目**，每条讲三件事：
多了什么 / 改了什么 / **你需要做什么**（大部分是"什么都不用做"）。

**「多了什么」「改了什么」里的每一项都要讲到，至少一句话，不要挑着讲。**
跨了好几版的，条目会很多，可以缩成一句一项，但不能漏 —— 尤其是会改变他用法的
（命令改名、多了一步要他选的、文件名换了），漏了他就不知道下次打命令时会发生什么。

再把 **skill 内容本身的改动**讲一句：哪几个 skill 的正文变了、大致改了什么。
用户信任的是仓库作者，他有权知道这次要执行的是什么。

**讲完直接装，不用再问一遍。** 他打 `/qa-更新`，就是已经同意更新了；再问"要装吗"，等于让他把同一个决定做两次。

只有这几种情况停下来问他，因为他的回答会改变你接下来怎么做：

- 第一位版本号变了（比如 1.x → 2.x）：这次可能要动他的项目，讲清楚要动什么，等他点头
- 他自己改过某个 skill：见第 6 步，问他覆盖还是保留
- 新版删掉了某个 skill：见第 5 步，问他删不删

他说的是「先看看有什么新的」「先别装」：只讲，不装，讲完结束。

## 5. 按 id 认领本地的 skill

扫 skill 目录下每个 `SKILL.md`，看 frontmatter 下面紧挨着的那一行 HTML 注释，
形如 `qa-ai-skill id=setup version=1.3.6`，只看其中的 `id`。**只认这一行**，正文里别处出现的不算。

**按 id 认，不按目录名认** —— 用户可能改过名字。

拿最新的 `版本.json` 逐项对：

| 情况 | 怎么处理 |
| --- | --- |
| 本地有，id 对得上 | 更新，走第 6、7 步 |
| 本地没有 | 新增的 skill，直接装 |
| 在 `已移除` 里，本地还有 | **列出来，说明原因，问他删不删** |
| qa- 开头，但没有 id 标记 | 不是这套装的。列出来，不要动 |

## 6. 查他有没有改过内容

每个要更新的 skill：取仓库 `v<本地版本>` 这个 tag 下的同一个目录，跟本地比。
**忽略目录名、`name:` 那一行，以及 id 那行注释里的 `version=` 和正文里写着版本号的地方** ——
前者是改名，后者每次发版都会变，都不是他改了内容。

取不到那个 tag，就当作改过。

- 一样 → 直接覆盖
- 不一样 → 他自己改过。**把改动列给他看**，让他选：
  1. 用新版，他的改动留在备份里
  2. 保留他的，这个 skill 这次不更新
  3. 你帮他把改动合进新版，合完先给他看一眼再写

## 7. 先备份，再覆盖

要被覆盖或删除的目录，先整个复制到 **skill 目录之外**，
比如用户主目录下的 `qa-ai-skill-备份/<日期>/`。

> 不能备份在 skill 目录里面。那里的每个子目录都会被当成一个 skill 加载，
> 备份一放进去，同一个命令就会出现两份。

覆盖时：

- **名字是谁改的，要分清**。拿本地目录名跟本地 `qa-更新/版本.json`（旧版）里这个 id 的 `目录` 比：
  - 一样 → 他没改过名。新版改了官方名字（比如 `qa-4-提bug` → `qa-5-提bug`），
    就**换成新名字**：旧目录备份后删掉，按新名字装，`name:` 也用新的
  - 不一样 → 是他自己改的名，**保留他的名字**，只换内容
- 按整个目录覆盖，不只是 `SKILL.md` —— skill 里可能还有别的文件
- 改了名的，收尾时告诉他：「XX 现在叫 YY 了」。他记住的命令变了，不说他会以为东西丢了

全部写完后，把最新的 `版本.json` 放进本地的 `qa-更新/` 目录。

## 8. 收尾

- 告诉他：更新了哪些、新增了哪些、哪些没动以及为什么、备份在哪
- 提醒**重启 AI 工具**才生效
- 如果当前目录是用 `/qa-1-建目录` 建过的项目（根目录有 `.qa-ai.json`），
  而更新说明里写了"需要补齐"，提示他跑一次 `/qa-1-建目录` ——
  它会只补缺的文件，已有的一个都不碰
- 项目里的目录还是英文名（`cases/`、`maps/` 这些），提一句：跑 `/qa-1-建目录` 可以改成中文，
  不改也照常能用。**这一步你自己不要去搬目录**，搬目录是 `/qa-1-建目录` 的事，要他点头

删掉临时目录。

## 不要做的事

- **不要碰用户项目里的任何文件。** `用例/`、`绑定/`、`测试数据/` 是他的资产，更新 skill 跟它们无关
- **不要自己决定删任何东西**
