# 更新这套 skill

仓库：https://github.com/monotcoder/qa-ai-skill

用户不懂命令行，全程你来做，每一步用大白话说你在干什么。

## 0. 先换成最新版的自己

把仓库克隆到一个临时目录（要带上 tag）。

如果仓库里的 `skills/qa-更新/SKILL.md` 跟你现在读的这份不一样，
**停下，改为照新版那份执行。**

更新的逻辑本身也会改。用旧逻辑去装新版本，出了错没人能修。

## 1. 找到 skill 目录

就是你读取 skill 的用户级目录。不确定就先查清楚，别猜。

## 2. 比版本

- 本地：skill 目录里 `qa-更新/版本.json` 的 `版本`
- 最新：临时目录里 `skills/qa-更新/版本.json` 的 `版本`

一样 → 告诉用户"已经是最新版"，删掉临时目录，结束。

## 3. 先讲清楚这次更新了什么，再动手

读临时目录里的 `更新说明.md`，**只挑本地版本之后的条目**，每条讲三件事：
多了什么 / 改了什么 / **你需要做什么**（大部分是"什么都不用做"）。

第一位版本号变了（比如 1.x → 2.x），说明可能要动他的项目，**讲完等他点头再继续**。

## 4. 按 id 认领本地的 skill

扫 skill 目录下每个 `SKILL.md`，看 frontmatter 下面紧挨着的那一行 HTML 注释，
形如 `qa-ai-skill id=setup`。**只认这一行**，正文里别处出现的不算。

**按 id 认，不按目录名认** —— 用户可能改过名字。

拿最新的 `版本.json` 逐项对：

| 情况 | 怎么处理 |
| --- | --- |
| 本地有，id 对得上 | 更新，走第 5、6 步 |
| 本地没有 | 新增的 skill，直接装 |
| 在 `已移除` 里，本地还有 | **列出来，说明原因，问他删不删** |
| qa- 开头，但没有 id 标记 | 不是这套装的。列出来，不要动 |

## 5. 查他有没有改过内容

每个要更新的 skill：取仓库 `v<本地版本>` 这个 tag 下的同一个目录，跟本地比。
**忽略目录名和 `name:` 那一行** —— 那是改名，不是改内容。

取不到那个 tag，就当作改过。

- 一样 → 直接覆盖
- 不一样 → 他自己改过。**把改动列给他看**，让他选：
  1. 用新版，他的改动留在备份里
  2. 保留他的，这个 skill 这次不更新
  3. 你帮他把改动合进新版，合完先给他看一眼再写

## 6. 先备份，再覆盖

要被覆盖或删除的目录，先整个复制到 **skill 目录之外**，
比如用户主目录下的 `qa-ai-skill-备份/<日期>/`。

> ⚠️ 不能备份在 skill 目录里面。那里的每个子目录都会被当成一个 skill 加载，
> 备份一放进去，同一个命令就会出现两份。

覆盖时：

- 他改过目录名或 `name:` 的，**保留他的名字**，只换内容
- 按整个目录覆盖，不只是 `SKILL.md` —— skill 里可能还有别的文件

全部写完后，把最新的 `版本.json` 放进本地的 `qa-更新/` 目录。

## 7. 收尾

- 告诉他：更新了哪些、新增了哪些、哪些没动以及为什么、备份在哪
- 提醒**重启 AI 工具**才生效
- 如果当前目录是用 `/qa-1-建目录` 建过的项目（根目录有 `.qa-ai.json`），
  而更新说明里写了"需要补齐"，提示他跑一次 `/qa-1-建目录` ——
  它会只补缺的文件，已有的一个都不碰

删掉临时目录。

## 不要做的事

- **不要碰用户项目里的任何文件。** `cases/`、`bindings/`、`seeds/` 是他的资产，更新 skill 跟它们无关
- **不要自己决定删任何东西**
