## 编号对照

旧编号的字母是当时 AI 自己起的，**没有固定含义**，每个项目都不一样。
所以没法给一张通用的表，要按这个项目的 `用例清单.md` 逐条对：

| 旧 | 新 | 怎么定 |
| --- | --- | --- |
| 用例 `X-01`、`B-02`…… | 「流程简称-序号」，如 `发布-01` | 看那条用例的 `流程:`，按 `/qa-3-出用例` 的规则起简称，序号保留原来的 |
| 疑似问题 `F-07` | `问题-07` | 序号不变 |
| 已知 bug `K-05` | `已知-05` | 序号不变 |

改编号时，每条用例和问题单里**留一行 `原编号: X-01`**。
旧报告里写的是旧编号，有了这一行，才能从旧报告查到现在是哪一条。

新旧编号对照**整张列给用户审**，流程简称他觉得不好懂就换。他点头才改。
不改也行：在 `.qa-ai.json` 里写 `"编号": "字母"`，老编号照常用，**新加的用例也接着用这个项目原来的格式**，一个项目里不要混两套。

## 老项目没改名时，每一步怎么找目录

`.qa-ai.json` 里写着 `"目录名": "英文"`，或者项目里就是 `cases/`、`maps/` 这些英文目录：

- 按上面这张表，把 skill 里写的中文目录换成对应的英文目录去找
- **不要新建中文目录**，不然同一份东西会出现两处
- 新建文件时放进英文目录里，名字照这个项目原来的习惯起

## 搬目录的步骤（用户点头之后）

1. 先确认工作区是干净的（没有没提交的改动）。不干净就停下，请用户先处理
2. 用 `git mv` 搬，**保留历史**。不在 git 里的项目，先整个复制一份备份
3. 改所有写着旧路径的地方：
   - `playwright.config.ts`（`testDir`、`storageState`）
   - `package.json` 的 npm 命令
   - `.gitignore`（登录态那一行一定要改，不然登录状态会被提交进仓库）
   - `脚本/`、`测试数据/` 里代码引用的路径
   - `CLAUDE.md` / `AGENTS.md` 里「测试相关」那一段
   - `项目适配.md` 里写到的路径：**这是用户的文件，逐条列给他看，他同意再改**
4. 执行 `git config core.quotepath false`
5. 全文搜一遍旧目录名，确认没有漏改的
6. 跑一次登录、跑一条用例，证明没搬坏
7. 编号要不要一起改，单独问一句（见上面「编号对照」）。改的话，用例 yaml、`用例清单.md`、
   问题单、`校准/已知bug.md`、脚本里的测试标题一起改，`项目适配.md` 里提到的编号列给用户看
8. `.qa-ai.json` 里删掉 `"目录名": "英文"`（如果有）
9. 收尾告诉用户：搬了哪些、改了哪些文件里的路径、哪些没改为什么

**已经存下的报告不用改里面的内容。** 旧报告里写的是当时的路径和编号，那是历史记录。
