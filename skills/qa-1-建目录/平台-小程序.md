# 平台 · 微信小程序

第 1 问答「微信小程序」时读这个文件。Web 读 `平台-web.md`，安卓 App 读 `平台-安卓.md`。

和另外两个平台一样，这里只讲六件事：怎么连上、怎么看界面、怎么定位、怎么知道在哪一页、
登录态怎么办、证据怎么留。六步骨架本身不变。

## 零、先问清楚：有没有源码

这一问决定了后面能不能自动走，**必须第一个问，答案写进 `项目适配.md`**：

| 情况 | 能做到什么 |
| --- | --- |
| **有源码**，能用微信开发者工具打开 | 全自动：AI 自己点、自己读页面、自己截图，和 Web 一样 |
| **只有体验版 / 线上版**，没有源码 | **不能自动走**。AI 不能驱动别人发布的小程序 |

没有源码时，这套流程退化成"用户走、AI 记"：用户在手机上点，AI 问他看到了什么、要他发截图，
再写进 `地图/` 和 `用例/`。第 3 步出用例、第 5 步提 bug 照常好用，只有第 2、4、6 步要人配合。
**这件事要在建目录时就跟用户说清楚**，不要等他跑到第 2 步才发现动不了。

## 一、怎么连上（有源码的情况）

靠微信开发者工具自带的自动化能力，官方库是 `miniprogram-automator`。

| 要什么 | 怎么查有没有 | 没有怎么办 |
| --- | --- | --- |
| 微信开发者工具 | Mac 看 `/Applications/wechatwebdevtools.app`，Windows 看安装目录 | 请用户自己装，给官网链接。安装包要点系统弹窗，本来就得他来 |
| 工具里开了「服务端口」 | 工具 → 设置 → 安全设置 → 服务端口 | **让用户自己去开**，这是个开关，AI 改不了 |
| Node.js | `node -v` | 请用户自己装 LTS 版 |
| `miniprogram-automator` | 项目里有 `node_modules/miniprogram-automator` | 问过用户再 `npm i miniprogram-automator`，几 MB |
| 小程序源码 | 用户给项目目录 | 见上面第零节 |

连上的方式有两种，**具体参数按官方文档核对**（工具版本不同，命令行参数会变）：

- 让脚本自己启动开发者工具并打开项目（适合每次干净启动）
- 开发者工具已经开着，脚本连上它的服务端口（适合反复调试，快）

连上之后，用的是**开发者工具里的模拟器**，不是真机。两者的差别见第七节。

## 二、怎么看界面：读页面数据，不要截图

和另外两个平台一个道理，**默认读结构，不截图**。小程序这边能拿到的比 Web 还多：

- 当前页面的路径和参数
- 页面的数据（小程序的 data），**这是别的平台没有的**：不用猜界面上那个数字是怎么来的，直接看数据
- 页面上的元素（按选择器查）

读到的东西写进 `地图/<模块>.yaml`，格式和 Web 一样。

**什么时候才截图**：样式错位、图片没加载、颜色不对。功能对不对，看数据和元素比看图准。

## 三、怎么定位一个元素

小程序的选择器写法像 CSS，但有两个坑，都要写进 `绑定/`：

| 情况 | 怎么办 |
| --- | --- |
| 普通元素 | 按 class 或 id 查，和 Web 一样 |
| **自定义组件里面的元素** | 不能直接从页面查到，要先拿到组件、再从组件里面查。**这是小程序最常见的"明明看得见却找不到"** |
| 列表里的第 N 个 | 查全部再取下标，不要写死索引到用例里 |

规矩不变：**选择器只能写进 `绑定/`，`用例/` 里一个都不许出现。**

## 四、怎么知道现在在哪一页

看当前页面的路径，比如 `pages/order/detail`，带上参数。这相当于 Web 的地址栏。

每一步操作之前先确认在哪一页，别假设上一步点完就一定跳过去了。小程序的
`navigateTo` 有层数上限（官方限制，**具体几层按官方文档核对**），层数满了跳转会静默失败，
页面不动——这正是"假设错了就会点空"的典型。

地图 yaml 里这样写：

```yaml
页面:
  订单详情:
    路径: pages/order/detail?id=xxx
    可点的:
      - { 名称: 确认收货, 类型: button, 状态: 禁点清单命中·没点 }
      - { 名称: 联系客服, 类型: button }
    数据: [订单号, 金额, 状态]
```

## 五、登录态

小程序的登录态在开发者工具里，跟着工具的登录微信号走，**不是一份可以换来换去的文件**。

- 一个角色跑完再换下一个
- 多角色要同时在线的，得用不同的微信号，**开发者工具同时只能登一个**，所以多角色要分批跑
- 后端认的是 openid，换微信号等于换用户，**测试数据也跟着换**，这点要提前跟用户确认
- 有测试号或者免登录的开发态入口的，优先用它，比换号快得多。有没有，问用户

## 六、证据怎么留

| 要什么 | 怎么来 | 注意 |
| --- | --- | --- |
| 截图 | 自动化库自带截图 | 开发者工具模拟器的截图，和真机的渲染可能有差别 |
| 页面数据 | 读当前页面的 data，存成 yaml | 比截图有用得多，**判定时优先看它** |
| 控制台报错 | 开发者工具的 Console | 小程序的报错很多只在控制台里，界面上看不出来 |
| 网络请求 | 开发者工具的 Network | 接口返回的原文，是"说不准"那一档最常要的证据 |

## 七、模拟器和真机不一样，报 bug 前先分清

开发者工具里跑通，不等于真机上没问题。这几类差异最常见：

- **性能**：工具里不卡，低端机上卡
- **系统能力**：定位、蓝牙、相机、支付，工具里多半是假的或者直接不支持
- **渲染**：字体、圆角、滚动惯性，工具和真机有出入
- **登录和支付**：真实支付**绝不在自动化里跑**，写进禁点清单

所以报 bug 时写清楚"在开发者工具里复现的"还是"真机上复现的"。
只在工具里出现、真机正常的，按「说不准」那一档处理，交给用户在真机上确认一次。

## 八、存成脚本用什么

就用 `miniprogram-automator` 本身，脚本跑在 Node 里，断言用项目已有的测试框架
（有 Jest 或 Mocha 就用它）。项目里已经在用别的，**用他们在用的，不要换**。

小程序的脚本有个 Web 没有的好处：可以直接断言页面数据，不用从界面上抠文字。
能断言数据就别断言界面文案——文案一改用例就红，数据不会。

## 九、禁点清单在小程序上要多问几条

- **真实支付**（哪怕一分钱）
- 发模板消息、订阅消息给真人
- 核销券、确认收货这类一按就不可逆的
- 会消耗额度的接口（短信、OCR、地图配额）
- 分享到群或朋友圈的动作
