# 第 1 步 · 建目录结构

## 先看是新建还是补齐

项目根目录**已经有 `.qa-ai.json`** → 这是老项目，走补齐：

- 不重新问六件事，读文件里存的答案；只问新版多出来的问题
- **只加缺的文件，已有的一个都不改** —— 里面可能已经写满了他的用例和绑定
- 补完更新 `.qa-ai.json` 里的版本号，告诉他补了哪些
- 没有 `项目适配.md` 的，按同目录的 `项目适配模板.md` 补一份；
  把从已有文件里看得出来的做法（用的什么工具、怎么登录）先填进去
- 项目的 AI 说明文件里没有那句提示的，补上（见下面「不走 skill 的时候也要读到」）

没有这个文件 → 新建，往下走。

## 先问这六件事，别直接生成

**按答案裁剪** —— 这是脚手架比模板仓库强的唯一理由。
模板给的是别人的结构，这里给的是他项目的结构。

1. **目标地址**？有没有独立的测试环境？
2. **登录怎么进**？账密 / SSO / 手机验证码 / 免登录
3. **哪些操作绝对不能点**？付款、发短信、注销、提交审核……
4. **bug 提到哪**？飞书多维表格 / Jira / 禅道 / TAPD / 先不提
5. **用什么工具测？** 项目里已经有测试工具就用它的；没有的话，Web 默认 Playwright，App 用宿主侧脚本。
   **不要替用户换掉他已经在用的工具**
6. **测一个系统，还是几个系统串起来？**
   - 就一个
   - 多角色：同一笔业务，几个端各做一步（买家下单 → 后台审核）
   - 上下游：数据从一个系统流到另一个（订单 → 库存 → 财务）
   - 两种都有

裁剪规则：

- 有验证码 → `seeds/` 里留"手工登录一次再存 storageState"的路径
- **没有独立测试环境 → 先明确警告**，然后把禁点清单调到最严
- 选了飞书 → 只生成飞书那版 `report-bug.ts`，别把四个平台都塞进去
- 第 6 问答"就一个" → **不生成任何跨系统的东西**，一行都不要
- 第 6 问答其他 → 读同目录的 `跨系统.md`，按里面的模板生成
- **第 6 问答了多角色或上下游，必须接着问**：有哪几个角色、各用什么账号、
  有没有不用登录的角色（比如消费者扫码页）。角色定不下来，后面的用例全是空的
- **出现高权限账号（运营后台、超管、能看所有租户的）时，单独问一句这轮测不测**。
  这种账号一读列表就可能看到别的客户的信息，风险跟普通账号完全不是一个量级。
  用户说测，再问清楚范围；用户没明说，就默认不测，写进禁点清单

## 目录

```
seeds/        登录态、造数据、fixtures.json
cases/        用例 yaml，不含任何选择器；外加一份 用例清单.md，一页纸列出有哪些流程
prompts/      01-explore / 02-no-touch / 03-verdict / 04-bug-report
maps/         AI 走出来的页面地图
bindings/     业务语言 → 真实路径（界面改只动这层）
tests/        跑通后固化的确定性脚本
reports/      每轮报告 + findings/ + evidence/
calibration/  已知 bug 校准集
项目适配.md    这个项目自己的做法，按同目录的 项目适配模板.md 生成
```

## skill 管"查什么"，`项目适配.md` 管"怎么做"

每个项目都不一样：用什么工具、怎么登录、怎么等页面加载、能不能并行跑。
这些**不写死在 skill 里**，写在项目自己的 `项目适配.md` 里：

- 每个 skill 开始前都先读它
- 做的过程中踩到新坑，往里补一条：做法、为什么、哪天发现的
- **skill 升级永远不碰这个文件**

### 不走 skill 的时候也要读到

用户经常不调 skill，直接说"帮我修一下这个测试"。这时候 AI 不知道有 `项目适配.md`，
踩过的坑又会再踩一遍。

所以在项目根目录的 **AI 说明文件**里加一段。这个文件每次在这个项目里对话，AI 都会自动读：

- 你自己是哪个工具，就用哪个工具的文件（Claude Code 是 `CLAUDE.md`，Codex 等是 `AGENTS.md`）
- 两个都已经有了，就两个都加
- 文件已经存在：**只在末尾追加这一段，不改原有内容**；已经有这一段就不再加

```markdown
## 测试相关

改测试相关的东西（tests/、seeds/、cases/、测试工具的配置）之前，先读 `项目适配.md`。
这个项目的测试工具、登录方式、怎么等页面加载、能不能并行跑，以及踩过的坑都在里面。
踩到新坑，往它的「踩过的坑」里补一条。
```

但下面四条规矩**不属于"怎么做"，任何项目都不准适配掉**。
生成 `项目适配.md` 时原样写在最上面。

## 禁点清单不止写操作

生成 `prompts/02-no-touch.md` 时，除了付款、发送、删除这些写操作，
**还要问一句：有没有"光是打开就会留下痕迹"的页面？**

常见的有：扫码量、阅读量、播放量会 +1；触发给真人的通知；消耗接口配额；
踩中风控被限流。这类页面不是不能打开，是**打开几次要有数**。

有这类页面，就在 `项目适配.md` 里建一张表，一次一行：

```markdown
### 副作用记录（每做一次记一行，报告里汇总）

| 日期 | 次数 | 谁做的 | 为什么 |
| --- | --- | --- | --- |
```

## 四条规矩必须写进生成的文件里

不是装饰，少一条这套就退化成普通自动化：

1. **`cases/` 里不准出现任何选择器。** 界面改了只动 `bindings/`。
2. **判定必须三档**：通过 / 失败 / 说不准。只给两档会逼 AI 硬判。
3. **路径偏离必须上报**，不准自己换条路把事做成 —— 绕过去，bug 就被埋了。
4. **禁点清单是第一优先级**，这是全流程唯一会造成真实损失的地方。

## 最后写一个 `.qa-ai.json`

放在项目根目录，以后更新和补齐都靠它：

```json
{
  "版本": "1.0.0",
  "答案": {
    "目标地址": "...",
    "独立测试环境": true,
    "登录方式": "...",
    "禁点": ["..."],
    "bug平台": "...",
    "端": "Web",
    "跨系统": "就一个"
  }
}
```

版本号读 skill 目录里的 `qa-更新/版本.json`，读不到就写 `"未知"`。

## 建完要讲清楚每个目录干啥

不能只列目录名。用户真正需要知道的是**哪个归他管、哪个归你管、界面改了动哪个**。
生成一张表，同时写进项目自己的 `README.md`，他随时能查：

| 目录 | 干什么 | 谁维护 | 界面改了要不要动 |
| --- | --- | --- | --- |
| `seeds/` | 登录态、测试数据 | 你建，用户登录一次 | 不用 |
| `cases/` | 用例，业务语言，不含任何选择器 | 你起草，**用户审** | 不用 |
| `maps/` | 页面地图 | 你 | 页面大改了就重走 |
| `bindings/` | 业务语言到页面位置的对照 | 你 | **界面改了只动这一层** |
| `tests/` | 跑通后固化的回归脚本 | 你 | 一般不用 |
| `reports/` | 每轮报告和证据 | 你 | 不用 |
| `calibration/` | 已知 bug 校准集 | 你和用户 | 不用 |
| `prompts/` | 禁点清单等说明 | **用户定**，你执行 | 不用 |
| `项目适配.md` | 这个项目的做法和踩过的坑 | 你写，用户看 | 不用 |

最后一列最值钱：**界面改了只动 `bindings/`**。这一句解释了为什么用例里不准写选择器。

## 生成完，先自己跑一次登录

装好依赖（按选定的工具来，Playwright 是 `npm i && npx playwright install chromium`），
**把存登录态的脚本跑一遍，跑通了才算建完**。生成的配置有错，用户第一步就会卡住。

常见的一个：Playwright 的登录脚本放在 `seeds/`，而全局 `testDir` 是 `./tests` ——
登录那个 project 要单独写 `testDir: './seeds'`，不然报 `No tests found`。

登录要密码的：**不要替用户输密码**。让他自己登录一次，存下登录状态
（Playwright 是 `npx playwright codegen --save-storage=seeds/.auth/<角色>.json <登录页>`），
密码不进任何文件。用户把密码发给你了，**明确拒绝使用，并建议他改密码**。

**存完必须验一次：拿这份登录状态打开首页，看落地在哪一页、页面上显示的是谁。**
没真正登录时文件照样会生成，大小跟有效的那份差不多，看文件根本看不出来。
脚本"跑通了"不等于"存对了" —— 这是这一步最容易过去的假通过。

顺手记下登录态的有效期，写进 `项目适配.md`。过期了用户得重新登录一次，
不然下一步所有用例都会卡在登录页。

## 名字怎么起

- **要在终端里敲的、要用户核对的，一律用英文**：登录态文件、目录名、npm 命令名。
  中文在有些终端里会显示成乱码，既看不清也敲不出来
- **这两个文件名是固定的，不准改**：`项目适配.md`、`用例清单.md`。
  后面几步的 skill 按名字找它们，改了就找不到
- 其余给人看的文档可以用中文名

## 收尾：照这个格式报，一条都不能少

1. **这一步动了哪些文件**：按目录分组，新增还是修改，每个一句话
2. **没动哪些**：列出来，让用户确认你没碰别的
3. **现在去看哪个文件**：指一个具体的，让他亲眼看产物。聊天记录会丢，文件不会
4. **这轮读了几屏、用的哪种读法、大约多少 token**
5. `项目适配.md`：补了 N 条（逐条列出）或 这次没补
6. **下一步打哪个命令**

这一步额外要说：**登录跑通了没有、存下的登录态验过没有**。

说完**停下**，不要自己接着走页面。下一步是 `/qa-2-走一遍页面`。

**别急着写用例。** 第一周唯一的验收标准是"任意页面 3 秒内能到达"，
而且这件事对手工测试当天就见效。
