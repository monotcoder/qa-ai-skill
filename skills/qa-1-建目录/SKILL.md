# 第 1 步 · 建目录结构

## 开口第一行：报版本

开始做之前，**第一行单独写**：

```
QA 流水线 v1.3.4 · qa-1-建目录
```

就这一行，不加别的话，像软件标题栏那样。直接写出来，不用放进代码块。
版本号就是这个文件开头那行注释里的 `version`，**不要去磁盘上读文件来报** ——
你报的必须是你现在加载的这一份。学员出问题时，作者靠这一行知道他跑的是哪一版。

接着顺手比一下（找得到就比，找不到就跳过，不要卡住）：

- skill 目录里 `qa-更新/版本.json` 的版本比你报的新 → 这个对话加载的是旧版。
  告诉用户「skill 已经更新了，但这个对话还在用旧版，请重启 AI 工具或者开一个新对话，再打这个命令」。
  他说「继续」，就照你现在这一版接着做，不要拦着
- 项目里 `.qa-ai.json` 的版本比你报的新 → 这个项目是更新的版本建的，提醒他先打 `/qa-更新`

这一步新写或改过的文档（地图、覆盖表、用例清单、报告、问题单、变更单），标题下面写一行
`生成：QA 流水线 v1.3.4 · qa-1-建目录 · <日期>`。改已有的文档，把这一行改成这一次的。

## 先看是新建还是补齐

项目根目录**已经有 `.qa-ai.json`** → 这是老项目，走补齐：

- 不重新问六件事，读文件里存的答案；只问新版多出来的问题
- **只加缺的文件，已有的一个都不改** —— 里面可能已经写满了他的用例和绑定
- 补完更新 `.qa-ai.json` 里的版本号，告诉他补了哪些
- 没有 `凭证.env` 的，按同目录的 `凭证模板.env` 补一份，`.gitignore` 里补上 `凭证.env`
- 没有 `项目适配.md` 的，按同目录的 `项目适配模板.md` 补一份；
  把从已有文件里看得出来的做法（用的什么工具、怎么登录）先填进去
- 项目的 AI 说明文件里没有那句提示的，补上（见下面「不走 skill 的时候也要读到」）
- **目录还是英文名的（`cases/`、`maps/` 这些，1.3.0 以前建的）**：按同目录的 `目录对照.md`
  把要改的名字逐个列给他，问改不改。这是整个补齐里唯一会动已有文件的地方，**他点头才改**：
  - 改：照 `目录对照.md` 里的步骤搬，搬完把登录和一条用例各跑一次，证明没搬坏
  - 不改：在 `.qa-ai.json` 里写 `"目录名": "英文"`，以后每一步都按英文目录找，照常能用
- **编号还是字母的（`X-01`、`F-07`）**：单独再问一次改不改，跟目录分开问。
  不改就在 `.qa-ai.json` 里写 `"编号": "字母"`，新用例接着用老格式

没有这个文件 → 新建，往下走。

## 先问这六件事，别直接生成

**按答案裁剪** —— 这是脚手架比模板仓库强的唯一理由。
模板给的是别人的结构，这里给的是他项目的结构。

1. **目标地址**？有没有独立的测试环境？
2. **登录怎么进**？账密 / SSO / 手机验证码 / 免登录
3. **哪些操作绝对不能点**？付款、发短信、注销、提交审核……
4. **bug 提到哪**？什么平台都行，说名字就好；还没有就「先不提」。
   再问一句：**AI 能不能动这个平台**？不关联（AI 不碰，每次出一张变更单你照着改）/ 只读 / 可写。
   **没想好就默认不关联**
5. **用什么工具测？** 项目里已经有测试工具就用它的；没有的话，Web 默认 Playwright，App 用宿主侧脚本。
   **不要替用户换掉他已经在用的工具**
6. **测一个系统，还是几个系统串起来？**
   - 就一个
   - 多角色：同一笔业务，几个端各做一步（买家下单 → 后台审核）
   - 上下游：数据从一个系统流到另一个（订单 → 库存 → 财务）
   - 两种都有

裁剪规则：

- 有验证码 → `测试数据/` 里留"手工登录一次再存 storageState"的路径
- **没有独立测试环境 → 先明确警告**，然后把禁点清单调到最严
- **这一步不接平台**，只把平台名字和关联方式记进 `项目适配.md`。真要接，到 `/qa-5-提bug` 那一步再带他接
- **但凭证的位置这一步就备好**：按同目录的 `凭证模板.env` 原样生成 `凭证.env`，常见平台都留好了空位，
  每一项写着去哪拿、要什么权限。用户到时候只填等号后面，不用自己想变量名、不用自己建文件
- **文件名用 `凭证.env`，不用 `.env`**。点开头的文件在访达和资源管理器里默认是隐藏的，
  用户打开文件夹看不到它，就会去填别的文件（实测：用户把凭证填进了模板）。
  告诉用户的时候说清楚**完整路径**，并提醒「填这个，不是模板」
- 第 6 问答"就一个" → **不生成任何跨系统的东西**，一行都不要
- 第 6 问答其他 → 读同目录的 `跨系统.md`，按里面的模板生成
- **第 6 问答了多角色或上下游，必须接着问**：有哪几个角色、各用什么账号、
  有没有不用登录的角色（比如消费者扫码页）。角色定不下来，后面的用例全是空的
- **出现高权限账号（运营后台、超管、能看所有租户的）时，单独问一句这轮测不测**。
  这种账号一读列表就可能看到别的客户的信息，风险跟普通账号完全不是一个量级。
  用户说测，再问清楚范围；用户没明说，就默认不测，写进禁点清单

## 目录

**所有层级的目录和文件都用中文名**，工具认死名字的除外（见下面「名字怎么起」）。

```
测试数据/
├─ 登录态/<角色>.json     每个角色一份登录状态，不进仓库
├─ 登录.setup.ts          存登录态的脚本
└─ 固定数据.json          测试要用的商品名、批次名这类固定值，不放密码
用例/
├─ 用例清单.md            一页纸列出有哪些流程、怎么点名
└─ <流程名>.yaml          业务语言，不含任何选择器
提示词/
├─ 01-走页面.md
├─ 02-禁点清单.md
├─ 03-判定.md
└─ 04-提bug.md
地图/覆盖表.md             全项目每个功能点走没走、有没有用例，第 2 步生成
地图/<系统>/<模块>.yaml    AI 走出来的页面地图（只有一个系统就不分 <系统> 这层）
绑定/界面.yaml             业务语言 → 页面位置（界面改了只动这层）
脚本/<流程名>.spec.ts      跑通后存下的回归脚本
报告/<日期>/
├─ 报告.md
├─ 疑似问题/问题-01.md
└─ 证据/<用例编号>-<说明>.zip / .yaml / .json
校准/已知bug.md            已知 bug 校准集
工具/                      接 bug 平台要写脚本时才有
项目适配.md                这个项目自己的做法，按同目录的 项目适配模板.md 生成
凭证.env                   bug 平台的凭证空位，按同目录的 凭证模板.env 生成，不进仓库
```

## skill 管"查什么"，`项目适配.md` 管"怎么做"

每个项目都不一样：用什么工具、怎么登录、怎么等页面加载、能不能并行跑。
这些**不写死在 skill 里**，写在项目自己的 `项目适配.md` 里：

- 每个 skill 开始前都先读它
- 做的过程中踩到新坑，往里补一条：做法、为什么、哪天发现的
- **skill 升级永远不碰这个文件**

### 不走 skill 的时候也要读到

用户经常不调 skill，直接说"帮我修一下这个测试"。这时候 AI 不知道有 `项目适配.md`，
踩过的坑又会再踩一遍。

所以在项目根目录的 **AI 说明文件**里加一段。这个文件每次在这个项目里对话，AI 都会自动读：

- 你自己是哪个工具，就用哪个工具的文件（Claude Code 是 `CLAUDE.md`，Codex 等是 `AGENTS.md`）
- 两个都已经有了，就两个都加
- 文件已经存在：**只在末尾追加这一段，不改原有内容**；已经有这一段就不再加

```markdown
## 测试相关

改测试相关的东西（脚本/、测试数据/、用例/、测试工具的配置）之前，先读 `项目适配.md`。
这个项目的测试工具、登录方式、怎么等页面加载、能不能并行跑，以及踩过的坑都在里面。
踩到新坑，往它的「踩过的坑」里补一条。
**不要打开 `凭证.env`**，里面是 bug 平台的凭证。脚本运行时自己读；要确认填没填，只让脚本报有没有。
```

但下面四条规矩**不属于"怎么做"，任何项目都不准适配掉**。
生成 `项目适配.md` 时原样写在最上面。

## 禁点清单不止写操作

生成 `提示词/02-禁点清单.md` 时，除了付款、发送、删除这些写操作，
**还要问一句：有没有"光是打开就会留下痕迹"的页面？**

常见的有：扫码量、阅读量、播放量会 +1；触发给真人的通知；消耗接口配额；
踩中风控被限流。这类页面不是不能打开，是**打开几次要有数**。

有这类页面，就在 `项目适配.md` 里建一张表，一次一行：

```markdown
### 副作用记录（每做一次记一行，报告里汇总）

| 日期 | 次数 | 谁做的 | 为什么 |
| --- | --- | --- | --- |
```

## 四条规矩必须写进生成的文件里

不是装饰，少一条这套就退化成普通自动化：

1. **`用例/` 里不准出现任何选择器。** 界面改了只动 `绑定/`。
2. **判定必须三档**：通过 / 失败 / 说不准。只给两档会逼 AI 硬判。
3. **路径偏离必须上报**，不准自己换条路把事做成 —— 绕过去，bug 就被埋了。
4. **禁点清单是第一优先级**，这是全流程唯一会造成真实损失的地方。

## 最后写一个 `.qa-ai.json`

放在项目根目录，以后更新和补齐都靠它：

```json
{
  "版本": "1.0.0",
  "答案": {
    "目标地址": "...",
    "独立测试环境": true,
    "登录方式": "...",
    "禁点": ["..."],
    "bug平台": "...",
    "bug平台关联": "不关联",
    "端": "Web",
    "跨系统": "就一个"
  }
}
```

版本号读 skill 目录里的 `qa-更新/版本.json`，读不到就写 `"未知"`。

## 建完要讲清楚每个目录干啥

不能只列目录名。用户真正需要知道的是**哪个归他管、哪个归你管、界面改了动哪个**。
生成一张表，同时写进项目自己的 `README.md`，他随时能查：

| 目录 | 干什么 | 谁维护 | 界面改了要不要动 |
| --- | --- | --- | --- |
| `测试数据/` | 登录态、测试数据 | 你建，用户登录一次 | 不用 |
| `用例/` | 用例，业务语言，不含任何选择器 | 你起草，**用户审** | 不用 |
| `地图/` | 页面地图 | 你 | 页面大改了就重走 |
| `绑定/` | 业务语言到页面位置的对照 | 你 | **界面改了只动这一层** |
| `脚本/` | 跑通后固化的回归脚本 | 你 | 一般不用 |
| `报告/` | 每轮报告和证据 | 你 | 不用 |
| `校准/` | 已知 bug 校准集 | 你和用户 | 不用 |
| `提示词/` | 禁点清单等说明 | **用户定**，你执行 | 不用 |
| `项目适配.md` | 这个项目的做法和踩过的坑 | 你写，用户看 | 不用 |

最后一列最值钱：**界面改了只动 `绑定/`**。这一句解释了为什么用例里不准写选择器。

## 生成完，先自己跑一次登录

装好依赖（按选定的工具来，Playwright 是 `npm i && npx playwright install chromium`），
**把存登录态的脚本跑一遍，跑通了才算建完**。生成的配置有错，用户第一步就会卡住。

常见的一个：Playwright 的登录脚本放在 `测试数据/`，而全局 `testDir` 是 `./脚本` ——
登录那个 project 要单独写 `testDir: './测试数据'`，不然报 `No tests found`。

登录要密码的：**不要替用户输密码**。让他自己登录一次，存下登录状态。
这条命令包成 npm 命令，用户只敲 `npm run login`，不用敲中文路径：

```json
"scripts": {
  "login": "playwright codegen --save-storage=测试数据/登录态/企业用户.json <登录页>"
}
```

密码不进任何文件。用户把密码发给你了，**明确拒绝使用，并建议他改密码**。

**存完必须验一次：拿这份登录状态打开首页，看落地在哪一页、页面上显示的是谁。**
没真正登录时文件照样会生成，大小跟有效的那份差不多，看文件根本看不出来。
脚本"跑通了"不等于"存对了" —— 这是这一步最容易过去的假通过。

顺手记下登录态的有效期，写进 `项目适配.md`。过期了用户得重新登录一次，
不然下一步所有用例都会卡在登录页。

## 名字怎么起

**目录和文件名一律用中文，每一层都是。** 学员是来学测试的，不该先背一套英文目录。

只有四类保留英文：

| 保留英文的 | 为什么 |
| --- | --- |
| 工具认死名字的：`package.json`、`playwright.config.ts`、`node_modules/`、`.gitignore`、`README.md`、`CLAUDE.md`、`AGENTS.md`、`.qa-ai.json` | 改了工具就找不到 |
| 工具认的后缀：`.spec.ts`、`.setup.ts`、`.yaml`、`.json`、`.zip` | 工具按后缀认文件，前面的名字用中文 |
| 工具自己生成的临时目录：`test-results/`、`playwright-report/` | 不进仓库、不用人维护，改了反而跟工具文档对不上 |
| 要敲的命令名：`npm run login`、`npm test` | 敲中文要切输入法；长的中文路径包进 npm 命令里，用户只敲命令名 |

还有几条：

- **建完目录马上执行 `git config core.quotepath false`**（只对这个项目）。
  不设的话，git 会把中文文件名显示成 `\346\265\213\350\257\225` 这种样子，用户会以为是乱码
- **编号也用中文**：用例是「流程简称-序号」（`批次-01`），疑似问题是 `问题-01`，已知 bug 是 `已知-01`。
  不用字母缩写 —— `X-01`、`R-02` 这种，除了起名的人谁也看不懂。规则见 `/qa-3-出用例`
- **这两个文件名是固定的，不准改**：`项目适配.md`、`用例清单.md`。
  后面几步的 skill 按名字找它们，改了就找不到
- 生成 `.gitignore` 时写上 `测试数据/登录态/` 和 `凭证.env`，登录状态和凭证绝不进仓库
- **`凭证.env` 生成之后你就不再打开它。** 用户填了值以后，你读它，值就进了对话记录。
  脚本运行时自己读；你要知道填没填，让脚本只报「有 / 没有」，不报值。
  用的是 Claude Code 的，在项目的 `.claude/settings.json` 里把 `Read(./凭证.env)` 加进 `permissions.deny`，告诉用户加了什么

## 提到的文件和编号，都写成能点开的链接

谁也记不住 `问题-07`、`已知-05` 底下是什么内容。所以：

- **对话里**：提到文件就写成 `[问题-07](报告/2026-10-10/疑似问题/问题-07.md)`，路径从项目根目录算
- **写进文档里的**（报告、变更单、用例清单、已知 bug、问题单）：每个编号、每个证据文件都写成链接，
  路径从**这份文档所在的目录**算（变更单在 `报告/2026-10-12/` 下，链 10-10 的问题单就写 `../2026-10-10/疑似问题/问题-07.md`）
- 编号链到它的出处：用例 → 那条用例所在的 yaml；问题 → 它的问题单；已知 → `校准/已知bug.md`
- **写完把每个链接对一遍文件在不在**。断掉的链接比没有链接更误导人
- 回放这种点开要下载的，链接旁边照样写上打开它的命令

## 收尾：照这个格式报，一条都不能少

1. **这一步动了哪些文件**：按目录分组，新增还是修改，每个一句话
2. **没动哪些**：列出来，让用户确认你没碰别的
3. **现在去看哪个文件**：指一个具体的，让他亲眼看产物。聊天记录会丢，文件不会
4. **这轮读了几屏、用的哪种读法、大约多少 token**
5. `项目适配.md`：补了 N 条（逐条列出）或 这次没补
6. **下一步打哪个命令**

这一步额外要说：**登录跑通了没有、存下的登录态验过没有**。

**收尾时把这几条念给用户听**，让他知道该挑什么毛病（他不会挑，就只能信你说的）：

- 打开 `提示词/02-禁点清单.md`：里面是不是他项目的具体东西，而不是模板原话
- 打开 `项目适配.md`：六个问题的答案是不是都落进去了
- 打开 `凭证.env`：他们用的那个平台有没有空位；`.gitignore` 里有没有 `凭证.env`
- 登录态是不是**验过**（拿它打开首页，看显示的是谁），不是只说"脚本跑通了"

说完**停下**，不要自己接着走页面。下一步是 `/qa-2-走一遍页面`：
它会先花几分钟读出整个站有哪些模块，再问他先跑一条核心流程尽快看到效果，还是全部走完。

**别急着写用例。** 第一周唯一的验收标准是"任意页面 3 秒内能到达"，
而且这件事对手工测试当天就见效。
