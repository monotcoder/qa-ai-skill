# 接平台 · 带用户把自己的 bug 平台接上

只在用户要接平台、或者要把关联方式从「不关联」换成「只读」「可写」时读这个文件。

**任何平台都行**：飞书多维表格、Jira、禅道、TAPD、GitLab、GitHub Issues、Linear、公司自己做的……
甚至是一张共享的 Excel。不要因为没听说过这个平台就说接不了。

用户多半没接过。**你来带，每一步用大白话说你在干什么、为什么。**

## 1. 先问清楚

- 平台叫什么，网址是什么（用的是平台官网上的云服务，还是公司自己部署的）
- bug 一般提到哪个项目、哪个表
- 他在平台上是什么角色（能不能建单、能不能改别人的单）
- 想用哪种关联方式。**没想好就建议先「只读」**：只能查不能改，出不了乱子

## 2. 查这个平台能怎么接，查官方文档，别凭记忆

按这个顺序找，找到一个能用的就停：

1. 平台官方的 MCP（AI 工具能直接调的那种）
2. 平台官方的命令行工具
3. 平台的开放接口（API）

**接口地址、参数、权限名字，一律以官方文档为准**，把文档链接给用户。
公司自己部署的老版本，接口可能跟官网文档不一样，以他那个版本的文档为准。

都没有，或者公司不让开接口：**直说接不了，用「不关联」**。
不关联照样能拿到大部分价值，见 `SKILL.md`。

## 3. 凭证：让用户自己建，权限越小越好

要连平台，得有一个凭证（令牌、密钥）。**教他自己去平台上建，你不碰它的值**：

- **权限最小**：只给那一个项目；只读方式只给"读"；可写方式只给"建单、改单、评论"。
  **不给删除权限，不用管理员账号建**
- 能设有效期的，设短一点，到期再续
- **填在项目根目录的 `凭证.env` 里**。建目录时已经生成好了，常见平台都有空位，
  告诉他填哪一段、哪几项就行。没有这个平台的空位，照着模板的样子帮他加变量名，值他自己填。
  没有 `凭证.env` 的老项目，按 `qa-测` 那个 skill 目录里的 `凭证模板.env` 补一份，先确认 `.gitignore` 里有 `凭证.env`
- **你不打开 `凭证.env`。** 值一旦被你读到，就进了对话记录。脚本运行时自己读，
  要确认填没填，让脚本只报「有 / 没有」
- `项目适配.md` 里**只写变量名**（比如 `FEISHU_APP_SECRET`），不写值
- **不要让他把凭证发到对话里。** 他发了：明确说不用它，请他去平台上把这个作废、重建一个

告诉他怎么断开：**去平台上把这个凭证作废，AI 就再也连不上了。** 他知道随时能断，才放心接。

## 4. 只读试一次

1. 读一张平台上**已有的**单，把读到的标题、状态、负责人列给他，请他打开网页对一下
2. 读出这个项目建单要填的字段：哪些必填、「严重程度」有哪几个可选值、「模块」有哪些
3. 整理成**字段对照**，写进 `项目适配.md`：

```markdown
| 我们这边 | 平台上的字段 | 怎么填 |
| --- | --- | --- |
| 严重程度：高 / 中 / 低 | 优先级 | 高 → P1，中 → P2，低 → P3 |
| 模块 | 所属模块 | 追溯页 → 消费端，企业端 → 管理后台 |
| 复现步骤 | 描述 | 放在描述的最前面 |
| 证据 | 附件 | 回放文件太大的，写路径，不传 |
```

有了字段对照，**不关联方式出的变更单也会按平台的字段来写**，用户粘贴更省事。

## 5. 给应用开表格的权限：加协作者，不准对全员放开

很多平台除了"接口权限"，还要**这张表、这个项目本身把应用加进来**，不然读得到、写不进（飞书报 403）。

- 正确做法：查官方文档里"把应用加为协作者"那一段，照着做。
  飞书是表格右上角「…」里的「添加文档应用」，**不是「分享」**；分享里只能搜到人。
  搜不到应用，一般是应用还没开"机器人"能力，开了再发布一个版本
- **不准为了让应用写进去，把表格改成"组织内所有人可编辑"或"任何人可编辑"。**
  那样公司里谁都能改这张 bug 表，比 AI 写错一条严重得多。你不要这样建议
- 用户已经这么改了：写完马上提醒他改回去，并告诉他正确的做法，下次照那个来

## 6. 要可写的，先试一张

1. 有测试项目、沙箱的，在那里试
2. 没有的：问他能不能建**一张**试用的单，标题写「QA测试-请忽略」
3. **建之前把要发出去的内容整张给他看**，他点头才发。
   他说「都写」也可以一次写完，但写之前把每一条的标题、严重程度、状态列成一张表给他过一眼
4. 建好了请他打开网页看一眼，字段都对再算接通。试用的单**由他自己删**，你不删

## 7. 写进 `项目适配.md`

```markdown
## bug 平台

- 平台：XX（网址）
- 项目：XX
- 关联方式：不关联 / 只读 / 可写
- 怎么连：官方 MCP / 命令行工具 / 开放接口（文档链接）
- 凭证：环境变量 BUG_PLATFORM_TOKEN，权限只有 XX，到期日 XX
- 字段对照：（上面那张表）
- 接通于：2026-10-12，试过：读了 TJT-100，建了一张试用单 TJT-131（用户已删）
```

需要写脚本才能连的，脚本放 `工具/` 下。

## 8. 收尾跟用户说清楚

- 现在是哪种关联方式，AI 能做什么、不能做什么
- 凭证在哪、什么时候到期、**怎么作废**
- 想换方式，直接说「改成只读」「改成不关联」，不用重接
