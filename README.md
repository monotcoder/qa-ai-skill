# QA 流水线 · 对话命令

把测试里重复的那部分交出去。**全程不用记一条命令行。**

| 命令 | 干什么 |
| --- | --- |
| `/qa-1-建目录` | 给你的项目建一套测试目录结构 |
| `/qa-2-走一遍页面` | AI 自己把站点点一遍，记下有哪些页面、怎么跳 |
| `/qa-3-出用例` | AI 起草用例，你审。不用自己写 |
| `/qa-4-跑测试` | 跑你点名的流程 + 通用巡检，出一份带证据、能回放的报告 |
| `/qa-5-提bug` | 把你确认的问题整理成完整缺陷单，连同要关的、要补充的，整理成一张变更单 |
| `/qa-6-存成脚本` | 把跑过的存成脚本，以后回归先跑脚本，不花 token |
| `/qa-更新` | 把这套 skill 更新到最新版 |

打 `/qa-` 会列出全部命令，**名字带编号，看编号就知道先后**。
列表显示的先后由工具自己决定，不用管它 —— 每个命令做完都会告诉你下一步打哪个。

## 第一次：先跑一条核心流程，还是全部走完

`/qa-2-走一遍页面` 会先花几分钟读出整个站的骨架：有几个模块、几个页面、几个表单。然后问你怎么跑：

| 跑法 | 好处 | 代价 |
| --- | --- | --- |
| **先跑核心流程**（推荐） | 半小时左右就能走到出报告，马上看到效果 | 只覆盖一条主干，其他模块没测 |
| **全部走完** | 一次把全项目摸清，用例是全量的 | 按骨架估时间，可能要一到几个小时，token 也多几倍 |
| **指定模块** | 只测这次改了的 | 别的不知道 |

**走到哪了，记在项目里的 `地图/覆盖表.md`**：每个功能点走没走、有没有用例，没有的写着原因。
只跑了一部分也没关系，以后随时打 `/qa-2-走一遍页面` 说「继续走没走的」，换了新对话也接得上。
每份报告开头都会告诉你全项目覆盖了多少。

## 什么时候打哪个

**1 到 3 是开头做一次的，4 到 6 是每次提测都转一圈的。** 不用从 1 走到 6。

| 遇到这种情况 | 打这个 |
| --- | --- |
| 接手一个新项目 | `/qa-1-建目录` → `/qa-2-走一遍页面` → `/qa-3-出用例` |
| 来了新需求、新功能 | `/qa-3-出用例` |
| 页面大改版了 | `/qa-2-走一遍页面`，说「页面改版了，重走 XX」 |
| 第一次只跑了核心流程，想补全 | `/qa-2-走一遍页面` 说「继续走没走的」，再 `/qa-3-出用例` |
| **开发说提测了 / 要发版了** | `/qa-4-跑测试` |
| 跑完有失败的 | `/qa-5-提bug` |
| 跑完有通过的、还没存成脚本 | `/qa-6-存成脚本` |
| 开发说某个 bug 修好了 | `/qa-4-跑测试`，说「跑 隔离-02」 |
| 改完平台上的单，要把单号告诉 AI | `/qa-5-提bug`，说「问题-07 建好了，单号 TJT-123」 |
| 不知道现在该干啥 | 随便打哪个都行，每个命令做完都会告诉你下一步打什么 |

**换了新对话也接得上。** 每条用例走到哪了——最近一次判定是什么、存没存成脚本、在等哪个 bug 修——
都写在项目里的 `用例/用例清单.md`，不靠聊天记录。

**一次一个。** 每个命令做完都会停下来，把结果交给你，你点头了再打下一个。
做的过程中它会边做边告诉你在干什么，你随时可以叫停。

**回归某个流程，直接说就行**：「跑批次发布」「跑批次-02 到批次-04」「全部跑一遍」「跑冒烟」。
有哪些流程、哪些编号，看项目里的 `用例/用例清单.md`。

**项目里的测试目录和文件都是中文名**（`用例/`、`报告/`、`地图/`……），打开就知道是什么。
只有工具认死的名字和要敲的命令名是英文。

**「通过」这两个字有门槛**：用例的预期是 AI 自己猜的，你没点头之前，
结果最高只能判「说不准」，不准判「通过」——不然就是拿系统证明系统，bug 会被判成通过。

## bug 平台：用什么都行，AI 不碰也行

**不限平台。** 飞书、Jira、禅道、TAPD、GitLab、公司自己做的，甚至一张共享表格都行。

**不放心让 AI 动平台，就不关联。** AI 照样把最费时间的活全做了：整理复现步骤、附证据、查哪些单该关、
哪些该重开、哪些可能重复，每次出一张**变更单**。你照着在平台上改，改完把单号告诉它。

想接上自己的平台，把这段话发给 AI：

```
我们团队的 bug 平台是 XX，网址是 XX。帮我把 /qa-5-提bug 接上它：
先查官方文档，看它能怎么接；再一步步教我建一个权限最小的凭证，凭证我自己存，不发给你。
先只读，不要建单、不要改单。接好了读一张已有的单给我对一下。
```

接好之后想放开，说「改成可写」；不放心了，说「改成不关联」，或者去平台上把凭证作废。
可写的时候，**每改一条之前都会先给你看、等你点头**。

## 每一步做完，怎么判断它做对了

看 [判断手册](判断手册.md)：每一步按顺序打开哪些文件、看什么、看到了说明什么、没看到说明什么，
还有哪几条碰到了这一步就不算过。**别只听 AI 说「做好了」，打开文件看。**

## 出问题了，先看版本

每个命令开口第一行都是版本，比如：

```
QA 流水线 v1.3.6 · qa-4-跑测试
```

它生成的每份文档（报告、用例清单、覆盖表……）标题下面也有一行 `生成：QA 流水线 v1.3.6 · qa-4-跑测试 · 日期`。

- **更新了但没生效**：它会自己发现，提醒你重启 AI 工具或者开一个新对话再打
- **要找作者求助**：把开口那一行，和出问题那份文档标题下面的「生成：」那一行，一起发过来

平时跑命令**不联网查新版本**，也不会每次都提醒你版本旧了。它比的只是这个对话加载的版本和你电脑上装的版本。

## 每个项目都不一样，这很正常

skill 只规定**查什么**和几条红线。**怎么做**——用什么工具、怎么登录、怎么等页面加载、能不能并行跑——
每个项目都不一样，由你的 AI 按你的项目来定，记在你项目里的 `项目适配.md`。

- 每个命令开始前都会先读它，踩过的坑不会再踩
- 遇到新情况，AI 会往里补一条
- **skill 升级永远不碰这个文件**

唯一不能"适配掉"的是四条规矩，见文末。

## 安装：把下面这段话复制给 AI

不用会 git，不用会命令行。打开你平时用的 AI 编程工具，把这段原样粘贴进去。

要用**能读写你电脑上文件的那种**，网页上的聊天框装不了。

```
帮我装一下这个仓库里的 skill：https://gitee.com/notcoder/qa-ai-skill
（同一个仓库在 GitHub 上也有：https://github.com/monotcoder/qa-ai-skill ，哪个快用哪个）

1. 把仓库克隆到一个临时目录
2. 把 skills/ 下面的每一个目录，都整个复制到你读取 skill 的用户级目录
   （所有项目都能用的那个位置，不是当前项目里）
3. 装完列一下装了哪些，再告诉我怎么验证装成功了

装之前先把每个 skill 的内容看一遍，有删文件、要密码、偷偷联网这类操作就告诉我。
不确定你的 skill 目录在哪，就先查清楚再装，别猜——装错位置你自己是读不到的。
如果你不支持 skill，直接告诉我。
如果我电脑上没有 git，先帮我装 git。整个过程你来做，我不懂命令行。
```

**过程中会弹出权限确认框，点允许就行**——那是 AI 在请求执行命令的权限，正常现象。

**AI 可能会先停下来问你两次，都是正常的：**

- 「是你自己想装的吗？」——整段都是粘贴来的，它要确认不是别人塞给你的。回「是我要装的」
- 看完 skill 内容后问「要装吗？」——先读一遍它列的审查结果，没问题就回「装吧」

## 验证装好了没

**重启你的 AI 工具**，然后打一个 `/qa-`，能看到上面表格里那些命令就成了。

有的工具不用斜杠调用，那就直接问它：「你现在有哪些 qa- 开头的 skill？」

没看到？把这句话发给 AI：

```
我装了 skill 但是用不了。帮我查一下：你读取 skill 的目录在哪，
那里有没有 qa- 开头的目录，每个目录里是不是都有 SKILL.md，有没有装错位置。
```

## 更新到最新版

打 `/qa-更新` 就行。它会：

- 先只查版本号，**没有新版就什么都不下载**
- 有新版就直接装，装的时候告诉你这次更新了什么、**你需要做什么**（大部分时候什么都不用做）
- 只有要动你的项目、你自己改过某个 skill、新版删掉了某个 skill 时，才会停下来问你
- 只想看看有什么新的、先不装：打 `/qa-更新` 时说一句「先看看，别装」
- 你改过名字的，照样认得出来，名字给你保留
- 你改过内容的，先把改动给你看，问你要不要覆盖
- 覆盖前先备份，备份在哪会告诉你
- 新版删掉的 skill，问你删不删，不会自己删
- **不碰你项目里的任何文件**

项目是旧版建的也没关系，旧项目照样能跑。新版多了什么，跑一次 `/qa-1-建目录` 就会补上缺的，已有的一个都不改。

每一版改了什么，见 [更新说明.md](更新说明.md)。

`/qa-更新` 用不了的话，把这句话发给 AI：

```
照 https://gitee.com/notcoder/qa-ai-skill 仓库里
（打不开就用 https://github.com/monotcoder/qa-ai-skill ）
skills/qa-更新/SKILL.md 的步骤，帮我把这套 skill 更新到最新版。
```

## 更新等于信任这个仓库

`/qa-更新` 会照仓库里最新版的说明去做。也就是说，**这个仓库的作者改了什么，你的 AI 就会照着执行**。

- 装之前让 AI 先把内容看一遍（上面那段话里已经写了）
- 更新时 AI 会告诉你这一版改了什么、你需要做什么；要动你项目的大版本，**会先停下等你点头**
- 想先看再决定，就说「先看看，别装」
- 不放心就让它把 skill 内容的改动也讲一遍再决定

这套东西本身不联网、不读你的密码、不往外发东西。但这条信任关系你得知道。

## 名字随便改

这些名字是我图省事起的，**你觉得别扭就改**。比如：

```
把你 skill 目录里的 qa-1-建目录 改名成 XXX，
记得 SKILL.md 里 name 那一行也要跟着改。
```

带数字前缀只是为了**打 `/qa-` 的时候它们按流程顺序排好**，
不然你得记住是先走页面还是先建目录。没有别的讲究。

改过名不影响更新：`/qa-更新` 按 skill 里一个固定的 id 认，不按名字认。

## 手动安装（兜底）

会命令行的话：

```bash
git clone https://gitee.com/notcoder/qa-ai-skill
```

Gitee 打不开就换 GitHub：`https://github.com/monotcoder/qa-ai-skill`，内容一样。

然后把 `qa-ai-skill/skills/` 下的所有目录，复制到你的 AI 工具的用户级 skill 目录。目录在哪，看它的文档。

## 四条规矩

这套东西跟普通 UI 自动化的区别全在这四条上，少一条就退化了：

1. **用例里不准出现任何选择器。** 界面改了只改 `绑定/` 那一层，用例一个字不动。
2. **判定必须三档**：通过 / 失败 / **说不准**。只给两档会逼 AI 硬着头皮下结论。
3. **走不通必须上报，不准自己换条路把事做成。** 绕过去了，bug 就被埋了 —— 这是最容易犯、代价最大的错。
4. **禁点清单是第一优先级。** 这是全流程唯一会造成真实损失的地方：
   别让 AI 在能发短信、能扣钱的环境里乱点。

---

## 一句话

**绿灯 ≠ 能发版，红灯 = 一定不能发版。**

自动化是变更检测器，不是正确性证明器。它提供证据，签字的是人。
