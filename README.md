# QA 流水线 · 四个对话命令

把测试里重复的那部分交出去。**全程不用记一条命令行。**

| 命令 | 干什么 |
| --- | --- |
| `/qa-1-建目录` | 给你的项目建一套测试目录结构 |
| `/qa-2-走一遍页面` | AI 自己把站点点一遍，记下有哪些页面、怎么跳 |
| `/qa-3-跑测试` | 跑用例 + 通用巡检，出一份带证据的报告 |
| `/qa-4-提bug` | 把你确认的问题整理成完整缺陷单，提到平台 |

打 `/qa-` 会自动列出这四个，按顺序排好，**不用记名字，也不用记顺序**。

---

## 安装：把下面这段话复制给 AI

不用会 git，不用会命令行。打开 Claude Code，把这段原样粘贴进去：

```
帮我装一下 QA 流水线的 skill：

1. 把 https://github.com/monotcoder/qa-ai-skill 克隆到一个临时目录
2. 把仓库里 skills/ 下的四个目录，整个复制到我的 Claude Code 用户级 skill 目录
   （Mac/Linux 在 ~/.claude/skills/，Windows 在 %USERPROFILE%\.claude\skills\）
3. 装完列一下装了哪几个

如果我电脑上没有 git，先帮我装 git。整个过程你来做，我不懂命令行。
```

**过程中会弹出权限确认框，点允许就行**——那是 AI 在请求执行命令的权限，正常现象。

## 验证装好了没

**重启 Claude Code**，然后打一个 `/qa-`。

看到这四条就成了：

```
/qa-1-建目录
/qa-2-走一遍页面
/qa-3-跑测试
/qa-4-提bug
```

没看到？把这句话发给 AI：

```
我装了 skill 但 /qa- 没反应，帮我检查 ~/.claude/skills/ 下有没有那四个目录，
每个目录里是不是都有 SKILL.md，有没有装错位置。
```

## 名字随便改

四个名字是我图省事起的，**你觉得别扭就改**。改法：

```
把我 ~/.claude/skills/ 下那四个 qa- 开头的目录改名成 XXX，
记得 SKILL.md 里 name 那一行也要跟着改。
```

带数字前缀只是为了**打 `/qa-` 的时候它们按流程顺序排好**，
不然你得记住是先走页面还是先建目录。没有别的讲究。

## 手动安装（兜底）

会命令行的话：

```bash
git clone https://github.com/monotcoder/qa-ai-skill && cp -r qa-ai-skill/skills/* ~/.claude/skills/
```

Windows 复制到 `%USERPROFILE%\.claude\skills\`。

## 四条规矩

这套东西跟普通 UI 自动化的区别全在这四条上，少一条就退化了：

1. **用例里不准出现任何选择器。** 界面改了只改 `bindings/` 那一层，用例一个字不动。
2. **判定必须三档**：通过 / 失败 / **说不准**。只给两档会逼 AI 硬着头皮下结论。
3. **走不通必须上报，不准自己换条路把事做成。** 绕过去了，bug 就被埋了 —— 这是最容易犯、代价最大的错。
4. **禁点清单是第一优先级。** 这是全流程唯一会造成真实损失的地方：
   别让 AI 在能发短信、能扣钱的环境里乱点。

---

## 一句话

**绿灯 ≠ 能发版，红灯 = 一定不能发版。**

自动化是变更检测器，不是正确性证明器。它提供证据，签字的是人。
